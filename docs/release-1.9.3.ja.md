# TenRiff 1.9.3: プレイ改善と外部モデル互換性

公開1.9.2を基に、先行するローカルONNXおよびプレイ・Safetensors変更を含みます。固定ソース基準は1.9.0で、旧タグ・配布物・インストール・プロファイルを保護します。公開状態・最終コミット・ダウンロードは[1.9.3リリースページ](https://github.com/10kseason/TenRiff/releases/tag/1.9.3)が基準です。この文書は実装範囲であり、最終検証の成功証拠ではありません。

## プレイと表示

- 空POORはゲージを減らしPOOR数と従来の素点・コンボ処理に残りますが、通常・詳細・区間精度から除外します。実ノートのミスとBADは精度を下げます。新規通常/HardはR7、EXはR8を使い、過去R1–R6の再生計算とボードIDを維持します。数値判定幅とリプレイ形式は変更しません。
- 選曲アルバム画像の右下に記述上のBMS RANKを4/3/2/1/0 → VEZ/EZ/NM/HD/VHDとして表示します。省略・不正値はEZです。RANK 4はメタデータ表示で、実判定の従来Easy代替は維持します。キャッシュ20で情報を再取得し、原譜面は変更しません。
- Classic・Studio・対戦ヘッダーでアーティスト名の横に赤いレベル欄を確保します。索引にないエディター練習・直接起動は実際の起動譜面のPLAYLEVELを使います。
- BMSの小節長・BPM/STOP・速度・スクロール位置に従う小節線をノート背後に表示します。判定・音声イベントを増やさず、osu!小節生成は含みません。
- 常時FAST/SLOWは最後の実測non-PG文字とマーカーを保持します。条件付きは750ms、文字・バーのスイッチは独立で、最初の入力前のFASTを捏造しません。
- 新規・設定省略時の読み込みは安全が既定です。保存済みの高速選択は維持し、独自LV/CR計算は別の既定OFF設定です。

## 外部BGAモデル

順序は元画像 → FFmpeg RGBデブロック → モデル固有倍率で推論 → 残差合成または完成画像 → 表示領域への調整 → 必要なクロップです。一般ONNXはRGB NCHW FP32/FP16の単一入力・単一出力契約内で任意のテンソル名、固定または完全動的な空間軸、均一な整数x1–x4に対応します。Autoは明示的な出力メタデータ、旧LunaSR2名の組、それ以外は完成画像の順に選びます。残差・完成画像の手動選択が優先し、Autoが画素値から意味を推測するわけではありません。

Safetensorsは任意のローカル変換経路です。対応LunaSR2 C32 R8/R12/R16 x2、または導入済みSpandrelの変換可能なRGB x1–x4構造を数値検証済みONNXに変換してWinMLへ渡します。利用者が導入したPythonとtorch/safetensors/onnx/onnxruntimeが必要で、一般構造にはSpandrelも必要です。隔離ワーカーは自動導入・モデル取得・pickle読込・モデル提供Python実行を行いません。非対応時は元画像とログ診断を維持します。[完全な契約と設定](../tools/onnx_upscaler/README.md)を参照してください。

**実行・ソース配布にBGAモデル重みは含みません。** 空パス・アップスケールOFF・出力Autoが既定です。既存NK3キー変換モデルは別機能として同梱します。静止BGAと選曲画像に対応し、動画AIは無効です。動的モデルは元寸法、固定モデルはパディング・文脈タイルを使い、モデル固有の寸法・演算・メモリ制約が残ります。

## 互換性と検証の境界

承認済み運用リーダーボード版19はR7/R8を別ボードで受け付け、過去記録・ID・Stable固定等級を維持します。ゲストと由来表示のない過去記録は永久に送信対象外で、後からOnlineを選んでも既存Guestプレイを昇格しません。Sitesはサーバーリプレイ検証ではなく`client_submitted`です。本ゲームリリースで追加のWeb・DB変更は不要です。

最終ビルド・独立展開ソース・CI・パッケージハッシュ・公開再取得は[検証手順](release-1.9.3-gate.md)に従います。先行ローカル成功は候補の証拠です。物理入力・音声、長時間プレイ、他PC、実アカウント運用送信、実Spandrelモデル、一般的な品質・性能は別の証拠が必要です。
