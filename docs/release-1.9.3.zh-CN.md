# TenRiff 1.9.3：游戏反馈与外部模型兼容性

此版本基于公开1.9.2，包含此前本地ONNX及游戏/Safetensors修改。固定源码基准仍为1.9.0，保留旧标签、发布文件、安装和配置。发布状态、最终提交及下载以[1.9.3发行页](https://github.com/10kseason/TenRiff/releases/tag/1.9.3)为准；本文说明实现范围，不代表最终检查已通过。

## 游戏与显示

- 空POOR仍扣血、计入POOR数量并保留原始分数和连击处理，但从普通、详细和分段准确率中排除。真正的漏音符和BAD仍降低准确率。新普通/Hard使用R7，EX使用R8，旧R1–R6回放计算和榜单ID保持不变。数值判定窗口及回放格式不变。
- 选曲封面右下显示作者标注的BMS RANK：4/3/2/1/0 → VEZ/EZ/NM/HD/VHD。缺失或无效值使用EZ。RANK 4只是元数据标记，实际判定仍使用原有Easy回退。缓存20重读信息，不改原始谱面。
- Classic、Studio及对战头部在艺术家旁保留红色等级区。没有索引匹配的编辑器练习和直接启动使用实际启动谱面的PLAYLEVEL。
- 在音符后绘制遵循BMS小节长度、BPM/STOP、倍率和滚动位置的小节线，不添加判定或音频事件；不包含osu!小节生成。
- 常显FAST/SLOW保留最后一次真实non-PG文字与标记。条件模式仍为750ms，文字与条形开关独立，首次反馈前不虚构FAST。
- 新建或缺失的加载设置默认安全。保留已保存的快速选择；原生LV/CR计算仍为独立默认OFF设置。

## 外部BGA模型

处理顺序为原图 → FFmpeg RGB去块 → 模型原生倍率推理 → 残差合成或完整图像输出 → 适配显示区域 → 按需裁剪。一般ONNX在RGB NCHW FP32/FP16单输入、单输出契约内支持任意张量名称、固定或完全动态空间轴及统一整数x1–x4倍率。Auto按明确输出元数据、旧LunaSR2名称组合、其余完整图像的顺序判断。手动选择残差或完整图像优先；Auto并非通过像素值推断模型语义。

Safetensors是可选的本地转换路径。受支持的LunaSR2 C32 R8/R12/R16 x2或已安装Spandrel中可导出的RGB x1–x4架构，先转换为经数值校验的ONNX再交给WinML。需要用户安装Python及torch/safetensors/onnx/onnxruntime，其他架构还需Spandrel。隔离进程不会自动安装、下载权重、载入pickle或执行模型提供的Python。失败时保留原图并记录原因。详见[完整模型契约和设置](../tools/onnx_upscaler/README.md)。

**运行包与源码包都不附带BGA模型权重。** 默认模型路径为空、放大OFF、输出Auto。原有NK3键数转换模型属于独立功能，继续附带。支持静态BGA和选曲图像，视频AI仍禁用。动态模型使用原始尺寸，固定模型使用填充及上下文分块，仍受模型尺寸、算子和内存限制。

## 兼容与验证边界

已经批准部署的正式排行榜版本19以独立榜单接受R7/R8，保留旧记录、榜单ID及Stable固定等级。访客和未标明来源的历史记录永久禁止上传；之后切换Online不能提升旧Guest游玩的上传资格。Sites仍为`client_submitted`，不是服务器回放验证。本游戏版本无需再次修改网站或数据库。

最终构建、独立解压源码、CI、包哈希及公开重新下载遵循[发布验证流程](release-1.9.3-gate.md)。此前本地通过结果仅是候选版证据。物理输入/音频、长时间游玩、其他电脑、真实账号线上上传、真实Spandrel模型以及普遍质量/性能需单独验证。
