# 1.8.9 Judge Easy / Hard 세션 전달 수정

Judge Hard를 선택했는데 실제 판정과 결과가 Normal로 남던 메뉴 시작 경로를 수정한다. R1–R4 판정 수치, 점수 공식, 리플레이 형식과 기존 기록은 바꾸지 않는다.

## 원인과 수정

Judge Easy / Hard는 기존 정책상 앱 실행 중에만 유지하는 선택이다. `build_persisted_runtime_config()`는 이를 프로필에 저장하지 않는다. 그런데 메뉴가 새 `GameSession`을 만들 때 선택값을 전달하지 않았고, 세션은 디스크의 프로필을 다시 읽었다. 이 때문에 화면에서 선택한 Judge Hard가 실제 플레이 전에 사라졌다. 결과와 리플레이의 `mods`도 실제로 적용된 Normal 상태로 저장됐다.

이제 메뉴가 현재 선택을 시작 직전에 명시적으로 전달한다. 세션은 프로필을 읽은 뒤 **세션 전용 판정 모드만** 복원한다. 다른 모드와 설정은 기존 프로필 경로를 계속 사용한다. 프로필 저장 정책을 바꾸는 것보다 이 경계를 수정하는 편이 기존 앱 재시작 동작과 저장 파일 호환성을 유지한다.

| 시작 경로 | 적용되는 판정 선택 |
| --- | --- |
| 메뉴에서 일반 플레이 / 재시작 | 현재 메뉴의 Judge Normal, Easy 또는 Hard |
| 메뉴에서 Normal 선택 | 이전 선택과 무관하게 Normal |
| 직접 실행 / headless, 별도 선택 전달 없음 | Normal; 디스크에 남은 예전 Judge 모드는 정리 |
| 리플레이 재생 | 원본 리플레이의 모드와 R1–R4 정책 우선 |
| 고스트 | 플레이어는 현재 선택, 고스트는 원본 리플레이 정책; 기존 호환 조건 유지 |
| 멀티플레이 | 기존 세션 규칙 우선; 로컬 Judge 모드를 적용하지 않음 |

앱을 종료하고 다시 켰을 때 Judge 선택이 Normal로 돌아오는 기존 정책은 유지한다. 과거에 Normal로 저장된 결과는 Hard로 소급 변경하지 않는다. 해당 결과에는 실제 Hard 판정으로 플레이했다는 근거가 없기 때문이다.

## 기록과 웹 리더보드

수정된 세션의 `active_mods`가 결과, 리플레이, 게임 내 기록과 웹 제출 데이터의 `mods`로 이어진다. 이 경로들은 이미 Judge 모드를 전달할 수 있었으므로 기록 마이그레이션이나 새 파일 형식은 필요하지 않다. 게임 내 조건 비교도 저장된 `mods`를 사용한다.

웹 소스 읽기 감사에서는 다음을 확인했다.

- `lib/leaderboard-contract.ts`: R4 제출을 허용하고 `mods`를 검증한다. 정렬한 `mods`는 보드 조건과 보드 ID 계산에 포함된다.
- `components/leaderboard.tsx`: 보드 조건의 `mods`를 화면에 표시한다.
- 게임의 `OnlineRecordsClient.cpp`: 보드 응답의 `mods`를 읽어 조건 라벨에 붙인다.

따라서 이 결함을 해결하기 위한 웹 코드 수정이나 배포는 필요하지 않다. `bms-easy` 같은 `timing_profile`은 채보의 BMS RANK를 뜻하며 Judge Easy 모드와 다르다. Judge Hard는 별도 `mods` 값으로 구분한다. 실제 신규 점수를 공개 사이트에 제출하거나 서버 데이터를 수정하는 작업은 이 검증에 포함하지 않는다. 로컬 웹 소스 감사는 공개 배포본의 실시간 동작 확인과 구분한다.

## 검증 경로와 한계

다음 회귀 검사를 추가했다. 실행 결과는 [1.8.9 릴리스 검증표](release-1.8.9-gate.md)에 기록한다.

- 프로필 저장 후 Judge 선택의 명시적 복원, Normal 선택, 다른 모드 보존.
- 실제 세션 초기화의 설정 단계에서 오래된 디스크 Hard 제거, 직접 실행, 멀티 우선순위, R1 Normal / R4 Easy 원본 리플레이 우선순위. 이 검사는 오디오 장치를 열기 전에 취소한다.
- 실제 메뉴의 Hard 선택 → `launch_gameplay()` → 결과의 Hard 메타데이터 연결.
- 합성 BMS `#RANK 3`의 네 노트에 각각 **+20ms** 표본을 주는 독립 세션: 기존 R4 규칙대로 Normal은 PG, Hard는 GR이어야 한다. 실제 세션을 초기화하고 무음 공유 오디오로 진행하며, 결과 저장·리플레이 재검증·로컬 결과 읽기·오프라인 웹 제출 데이터까지 확인한다.
- Normal / Easy / Hard 웹 제출 모드와 보드 응답 라벨의 구분.

합성 입력은 샘플 시각을 지정해 제품의 레인 입력 경로로 전달한다. 판정과 저장 경로의 회귀 검사이며 물리 키보드 지연, 귀로 듣는 동기, 다른 PC, 장시간 플레이 또는 실제 웹 제출 성공을 입증하지 않는다. 사용자 프로필과 사용자 채보를 테스트 입력으로 사용하지 않는다.
