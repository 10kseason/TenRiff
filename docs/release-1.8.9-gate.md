# TenRiff 1.8.9 릴리스 범위와 검증

이 문서는 **1.8.9 소스의 동작과 완료한 로컬 검증 범위**를 기록합니다. 런타임 검사와 남은 패키지·CI·공개 단계를 아래에서 구분합니다. [1.8.9 릴리스와 다운로드](https://github.com/10kseason/TenRiff/releases/tag/1.8.9)는 이 버전의 배포 대상 링크이며, 이 문서 작성만으로 공개 완료를 뜻하지 않습니다. 작업 출발점은 1.8.8 커밋 `e279f3468250148d5732bd53e354860563774c25`이고, 사용자 고정 기준은 계속 [1.8.7](baseline-1.8.7.md)입니다. 기존 1.8.7·1.8.8 태그와 배포 파일을 교체하지 않습니다. 이전 배포 설명은 [1.8.8 릴리스 기록](release-1.8.8-gate.md)에 보존합니다.

## 화면과 조작

기본 로비의 BEST는 각 열 전체에 같은 의미별 색을 사용하며 라벨 24px·주 숫자 42px·보조 설명 22px를 기준으로 맞춥니다. 점수의 최대값과 상세 점수, 콤보의 단위를 주 숫자 아래로 분리합니다. 왼쪽 목록과 가운데 아트/BEST/필터는 기존 내부 패널을 유지하면서 하나의 흰색 2.4px 둥근 외곽선으로 묶습니다. 활성 Start 버튼은 결과의 Continue와 같은 하늘색을 사용합니다.

메타 정보는 기존 4열의 공통 최소 축소 비율을 없애고 2×2 영역에 24px 라벨과 36px 값 글꼴을 각각 맞춥니다. 긴 노트 수 때문에 BPM·레벨까지 작아지던 결합을 제거한 것입니다. 노트 수는 흰색, BPM·레벨·NPS는 각각 다른 색으로 표시합니다. 실제 크기는 선택 글꼴·문자열·창 크기와 스킨 영역에 따라 줄어들 수 있습니다. 의미별 색은 단색 테마 변환을 거치지 않으며 S+ 등급 색·글꼴은 바꾸지 않습니다. 외부 이미지 로비 스킨은 기존 배치를 유지합니다.

`Options > Skins`에서 Studio Deck 또는 Classic을 선택합니다. Studio Deck은 Native·가져온 LR2 스킨의 단독 플레이에 적용하며 LR2 노트·건반·기어를 유지합니다. 고스트 대전·멀티플레이·다른 이미지 스킨은 Classic 배치를 유지합니다.

- 곡 제목과 Rate/HS/BPM/Scroll/Line/Latency는 오른쪽 위에, 점수·정확도·판정 수는 왼쪽 아래에 배치합니다.
- 64구간 노트 밀도 그래프는 오른쪽 아래의 가로 riff map으로 표시하며 시간은 왼쪽에서 오른쪽으로 진행합니다. 현재 위치·경과/전체 시간을 표시합니다. `Options > Skins > Studio Riff Map`으로 끄고 프로필·스킨 프리셋에 저장할 수 있습니다.
- 필드 바깥 여백이 좁으면 카드 전체를 비례 축소하고, 선호하는 쪽 공간이 부족하면 더 넓은 반대쪽으로 옮깁니다. 점수와 맵이 같은 쪽에 모이면 점수를 위로 올려 분리합니다. 매우 좁은 맵은 시간 글자를 생략합니다.
- Performance HUD가 있으면 상단 정보 카드만 안전한 반대쪽을 찾습니다. 극단적으로 넓고 왼쪽에 붙은 필드와 Performance HUD가 겹쳐 양쪽 상단 공간이 모두 없으면 **상단 정보 카드만 숨깁니다**. 점수와 맵은 남으며, 맵을 숨겨도 다른 카드 위치는 바뀌지 않습니다.
- 게이지 레일은 4→6px, 마커는 62×27→76×32로 확대합니다. 극우측 필드에서는 마커를 필드 왼편으로 옮깁니다. 게이지 계산과 노트·건반·판정·콤보의 플레이 영역은 바꾸지 않습니다.

단독 결과 화면의 `SUMMARY / LANES / NOTE TYPES / TIMELINE`은 각각 버튼 형태로 표시합니다. 왼쪽 정보 그룹에는 통합 외곽선과 내부 구분을, 분석에는 초록 테두리를 사용합니다. 점수 116px·주 정확도 64px·통계 52px·가운데 정렬한 메타 정보 36px·라벨/본문 24px·조작 30px 전용 글꼴을 영역에 맞춥니다. 통계 열은 필요한 폭을 다르게 배정해 긴 백분율의 줄바꿈을 방지하며 MAX COMBO 숫자와 단위를 분리합니다. Replay/Retry 아이콘과 글자는 측정한 묶음 폭을 기준으로 가운데 정렬하며 Continue는 하늘색으로 구분합니다. 기존 `Enter` 복귀, `R` 재시도, `F1` 리플레이와 `F9` PNG 저장 동작은 유지합니다. 프로필 외곽선의 Gaussian bloom은 크기·색이 같을 때 작은 비트맵을 재사용합니다.

## Judge 선택 전달

Judge Easy/Hard는 원래 프로필에 저장하지 않는 세션 전용 선택입니다. 이전 메뉴 시작 경로는 메모리의 선택을 새 GameSession에 전달하지 않아 디스크 재로드 후 Normal로 실행·기록했습니다. 현재 메뉴 선택을 시작 직전에 명시 전달하도록 수정했으며, 앱 재실행 후 Normal로 돌아오는 저장 정책은 유지합니다. 리플레이는 원본 모드와 ruleset, 멀티플레이는 기존 공통 규칙을 우선합니다. 과거 Normal 기록을 Hard로 소급 변경하지 않습니다.

R1/R2/R3/R4 판정 수치·점수·파일 형식은 그대로입니다. 웹 소스는 이미 `mods`를 보드 조건·ID·표시에 사용하므로 이 수정에 웹 코드 배포나 마이그레이션은 필요하지 않습니다. 공개 사이트의 신규 제출이나 실제 표시 성공은 아직 검증한 것으로 기재하지 않습니다. 원인·시작 경로·검사 설계는 [Judge 세션 전달 수정](judge-session-handoff-1.8.9.ko.md)을 참고하세요.

공개 페이지가 참조하는 JavaScript를 읽어 선택 보드의 `mods` 태그 렌더 코드가 포함됨을 확인했습니다. 보드 목록 자체에는 모드 라벨이나 전용 Judge 필터가 없습니다. 코드 존재 확인은 신규 점수 업로드·선택 보드의 실제 표시·계정 연동의 전체 경로 검증과 구분합니다.

## 성능 측정과 잔여 한계

최종 비교는 1.8.8 기준과 1.8.9 후보를 6회 AB/BA 교대로 실행했고, 각 실행 3,000 프레임·합계 **108,000 successful Presents**를 기록했습니다. 수치는 `Present`를 포함하는 합성 CPU 렌더 호출의 실행별 백분위 중앙값이며 단위는 ms입니다. 물리 입력 지연이나 GPU 처리량 측정이 아닙니다.

| fixture | p50 기준 → 후보 (차이) | p95 기준 → 후보 (차이) | p99 기준 → 후보 (차이) |
| --- | --- | --- | --- |
| tap16-pressed | 1.23760 → 1.11425 (**−0.12335**) | 1.88535 → 1.84590 (**−0.03945**) | 2.38095 → 2.35050 (**−0.03045**) |
| native LN | 1.29590 → 1.29920 (**+0.00330**) | 1.97380 → 1.88500 (**−0.08880**) | 2.48935 → 2.39390 (**−0.09545**) |
| ghost LN | 1.86590 → 1.88625 (**+0.02035**) | 2.64390 → 2.69515 (**+0.05125**) | 3.14460 → 3.07340 (**−0.07120**) |

세 fixture의 p50 차이는 기존 **+0.03ms** 목표 안입니다. 그러나 ghost p95는 **+0.05125ms, 약 +1.94%**이므로 **엄격한 p95/p99 비증가 기준은 충족하지 못했습니다**. 이 증가를 남은 한계로 명시하며 성능 검사 전체 통과나 일반적인 성능 개선을 주장하지 않습니다.

첫 6회 비교의 p50 증가 tap16 **+0.0562ms**, native LN **+0.0037ms**, ghost LN **+0.03455ms**도 보존합니다. 별도 2회·12,000 Presents 진단에서는 Studio 맵을 끈 tap16의 p50/p95/p99 차이가 **+0.00200/−0.03055/−0.06205ms**, Classic은 **−0.01005/+0.05650/+0.10885ms**였습니다. 이후 일반적인 298px 맵에서 시계가 불필요하게 소수 비율로 축소되지 않도록 최소 맞춤 폭을 320→280px로 조정하고, Studio가 비활성일 때 레이아웃 계산을 생략했습니다. 최초·진단·최종 측정의 절대 기준 시간이 서로 다르므로 이 변경 하나가 결과 차이의 유일한 원인이라고 결론내리지 않습니다.

최종 표시 검사에서는 흰 노트 수, 로비 통합 외곽선, 큰 BEST·통계·정확도와 가운데 메타 정보, 정상적인 `⑤ LEVEL 18`의 Unicode 전달·표시를 확인했습니다. Start/Continue 각각의 검사 영역에서 하늘색 픽셀이 50% 이상임을 확인했고 S+ 영역은 기준과 픽셀 동일합니다. 잘못 보이던 특수 문자는 미리보기 도구의 ANSI 명령행을 UTF-8로 취급한 경로를 Windows Unicode 명령행 처리로 고친 것이며, 제품의 레벨 라벨 선택 방식은 유지합니다. 별도의 최종 40개 화면 검사도 위 표에 반영했습니다.

남은 단계는 패키지 ZIP CRC·해시·개인정보 제외·소스 일치와 추출 소스 독립 빌드입니다. PR/main CI, 태그와 원격 자산 공개, 익명 다운로드 해시 확인은 별도 완료 증거가 필요합니다. 이 소스 문서는 공개 완료 증명이 아니며, 소스 확정 뒤의 패키지·원격 전달 결과는 릴리스 설명과 외부 검증 기록에 남깁니다.

## 유지할 경계

원본 채보·기존 프로필·설치와 과거 배포물을 보존합니다. 1.8.7의 고정 기준을 자동으로 올리지 않습니다. 1.8.8의 분석 정의, 긴 LN Mix v2의 로컬 기록/리플레이 전용 및 기존 BEST·Sites 제외 정책은 별도 변경이 검증되지 않는 한 유지합니다. [플러그인 실행 환경·API·SDK와 1.9.0 안정화](result-analysis-1.8.8.ko.md)는 계속 계획입니다.

물리 입력·청감·장시간 플레이·다른 PC·실제 온라인 대전은 해당 검사를 수행하기 전까지 미검증으로 남습니다. 합성 화면·단위 검사·소스 검토를 이 범위의 성공으로 확대하지 않습니다.
