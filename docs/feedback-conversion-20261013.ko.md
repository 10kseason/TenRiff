# 1.8.9 기반 로컬 피드백 수정

사용자가 지정한 1.8.9의 UI와 수정 사항 위에 적용한 로컬 패치다. 공개 1.8.9와 고정 기준선 1.8.7, 기존 설치·프로필은 보존한다.

## 변환과 BMS 호환

`we are the 5KHD.bms`는 `#LNOBJ ZZ`를 사용한다. 원본 로딩은 1,631개 노트 중 롱노트 21개를 올바르게 읽었으나, 변환 뒤 공통 겹침 정리에서 꼬리가 잘리거나 짧은 노트로 바뀌었다. 따라서 파서의 LNOBJ 해석을 바꾸지 않고 변환 경계를 수정했다.

Krrcream·nK2(세 프리셋)·NK3 모두 원본 롱노트의 시작/끝을 먼저 확보한다. 변환기가 제안한 레인을 우선 사용하고 충돌하면 가까운 빈 레인을 찾는다. 키 수보다 많은 롱노트가 동시에 점유하는 경우 모든 누름을 유지할 수는 없다. 기존 롱노트를 자르지 않고 배치 불가능한 노트를 제외하며, 해당 키음은 원래 시각의 배경음으로 보존한다. 일반 노트도 같은 시각/같은 레인 중복이나 롱노트 내부 충돌을 피한다.

이전 키음 보존은 일부 키 수 감소 경로에만 적용됐다. 이제 증가/감소, 그룹별 DP 변환 및 공통 변환 호출에 적용한다. 이미 재생될 같은 시각·같은 음원은 추가하지 않고, 서로 다른 음원과 기존 BGM의 중복은 보존한다. BMS 파일 출력은 누락된 키음을 각각 독립된 `#xxx01` 줄에 기록해 동시 음원이 서로 덮이지 않도록 한다. 곡의 음원 파일 자체는 변경하지 않는다.

## 예전 리플레이와 고스트

사용자가 승인한 선택적 `mode.key_conversion_version`은 리플레이에서 생략/1이면 1.8.9 변환, 2이면 수정된 변환이다. 결과 JSON에도 같은 필드를 기록한다. 알 수 없는 값은 거부한다. 새 플레이는 2를 기록하고, 예전 리플레이는 원래 패턴으로 재생한다. 두 필드가 같은 차트를 사용하는 고스트 대결은 검증된 고스트의 변환 버전을 채택하고 결과에도 그 버전을 남긴다. 판정 규칙 R1–R4와 리플레이 포맷 번호는 변경하지 않는다.

구버전 클라이언트는 새 변환을 구현하지 않으므로 새 변환 리플레이의 정확한 재생에는 이 패치가 필요하다. 이 작업에는 웹 배포나 랭킹 서버 변경이 포함되지 않는다.

## 화면과 입력

- 키 지정이 저장되면 같은 기본/보조 슬롯의 다음 키로 이동해 입력을 계속 받는다. 마지막 키에서 종료한다. 키 반복, 저장 실패, 취소, 시간 초과, 보조 키 삭제로 연속 지정하지 않는다.
- Options › Skins › HUD의 인디케이터 배경은 FAST/SLOW·타이밍 배경을 제어한다. P GREAT·GREAT·GOOD 등의 판정 글자는 항상 둥근 테두리와 배경 없이 표시한다. 정보 카드와 실제 피드백 글자/눈금/마커는 별도로 유지한다. 기본값은 켬이며 프로필·프리셋에 저장된다. 웹 스킨 형식에는 추가하지 않았다.
- 스킨 설정의 작은 미리보기와 F6 전체화면 모두 기어 오른쪽 위 위치 핸들을 드래그할 수 있다. 미리보기 배율에 맞춰 이동 거리를 환산하고, 놓으면 실제 플레이에 쓰는 위치를 프로필에 저장한다. 화면 경계에서 제한하며 드래그 중 다른 화면으로 전환하면 미저장 이동은 취소한다.
- Studio 세로 게이지 폭은 6→10, 수치 배지는 76×32→96×40으로 확대했다. 기본 Classic 게이지 폭은 46→60이며 주변 여백도 늘렸다. 외부 스킨이 직접 지정한 게이지 사각형은 존중한다. 게이지 계산과 판정은 동일하다.
- 고스트 대결은 양쪽 확대 게이지가 화면 안에 들어오도록 고스트 필드의 남는 폭을 조정했다. 플레이어 필드와 노트의 물리적 크기는 솔로와 동일하게 유지한다.

## 재현 검사

`bms_parser_tests --filter="feedback regression"`는 변환/음원/내보내기/리플레이/설정 회귀만 실행한다. 전체 CTest는 기존과 동일하게 모든 테스트를 실행한다. 선택적으로 `TENRIFF_BMS_FEEDBACK_CHART`에 보고된 BMS의 경로를 주면 원본 21개 롱노트의 시작/끝 보존을 검사한다. 지정하지 않으면 배포 가능한 작은 합성 LNOBJ 패턴을 사용한다. 보고된 원본 BMS와 개인 경로는 배포물에 넣지 않는다.

음원 일정과 합성 WAV의 로딩 검사는 실제 곡의 소리를 사람이 들은 증거가 아니다. 실제 키보드/오디오 체감, 장시간 플레이와 다른 PC 검증은 별도다. 최종 실행 로그와 화면 증거는 작업 폴더의 `evidence/VERIFICATION.ko.md`에 기록한다.
