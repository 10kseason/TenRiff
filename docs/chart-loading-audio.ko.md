# 차트 로딩 중 오디오 간섭 완화

대상: 1.8.6에서 보고된 WASAPI 차트 로딩 중 게임/음성채팅 동시 끊김.
제보에서는 로딩 후 연주 중 음성채팅은 정상이며 ASIO는 사용하지 않았다.

## 확인한 경로와 변경 이유

- 기존 GameSession::initialize는 차트 분석 전에 프로필 샘플레이트로 장치를 열었다.
  차트 음원이 다른 레이트이면 장치를 닫고 다시 열었으며, 파싱 실패/취소도 첫 장치 개방 뒤에 처리했다.
  44.1 kHz 설정과 48 kHz 음원의 기존 실행 로그에서 이 재개방을 확인했다.
- 새 순서는 장치 없이 차트 분석 → 음원 레이트 확인/타임라인 재생성 → 장치 개방이다.
  일반적인 성공 경로는 한 번만 개방한다. 요청 레이트 실패 시 설정 레이트로 복귀하며,
  드라이버의 실제 레이트가 다르면 그 레이트로 타임라인을 다시 만든다.
  이미 반올림한 노트 시간을 비례 변환하지 않아 기존 샘플 단위 계산을 보존한다.
- 로딩 화면도 Gameplay 화면으로 분류되어 게임의 높은 FPS 설정을 사용했다.
  로딩/대기 카드에만 60 FPS 상한을 적용하고, 첫 카운트다운/플레이 HUD 콜백에서 기존 페이싱을 복원한다.
  설정 파일, VSync, 디스플레이 모드/주사율은 바꾸지 않는다.

공유/독점 선택과 ASIO의 지정 레이트 정책은 유지한다. 독점 모드는 Windows 설정에 따라 다른 공유 스트림을
선점할 수 있으므로, 이 수정이 독점 재생과 음성채팅의 동시 출력을 보장하지는 않는다.
근거: [Microsoft WASAPI 독점 스트림 문서](https://learn.microsoft.com/en-us/windows/win32/coreaudio/exclusive-mode-streams).

## 검증

- 단위 회귀: 로딩 취소/실패 시 장치 개방 없음, 로딩 상한/플레이 복원/설정 불변.
- menu_app_smoke: 실제 메뉴 렌더러의 로딩 카드 Present 수 및 메뉴→플레이→결과→메뉴,
  별도 세션의 일시정지/재개.
- loading_audio_smoke NEW_SANDBOX: 38,400 노트 합성 차트, 44.1/48 kHz 각 2회,
  무음 WASAPI 공유 스트림을 동시 실행. 파싱 단계 장치 미개방, 실제 레이트/전체 노트 상대시간,
  동시 스트림 콜백 진행 여부와 최대 간격을 기록한다.
  관찰을 위한 단계별 200 ms 대기가 있으므로 총 실행 시간을 로딩 성능으로 해석하면 안 된다.
- 관찰 도구는 마이크/데스크톱 음원을 캡처하지 않으며 기존 폴더를 대상으로 실행하지 않는다.

로컬 공유 스트림에서는 수정 전에도 제보된 가청 끊김은 재현되지 않았다.
장치 조기 개방과 고 FPS 로딩 경로는 재현/회귀 대상이지만, 제보자의 장치·드라이버·실제 차트·음성채팅을
이용한 증상 해소 확인은 별도로 필요하다. 이 문서의 로딩 순서·FPS 상한 변경 자체는 판정, 입력, 믹서,
게이지/점수, 리플레이 규칙과 노트 배칭 경로를 바꾸지 않는다. 같은 시험본의 별도 싱크 수정은
[입력 보정](input-offset-timing.ko.md) 및 [콜백 관측 시각](audio-callback-timestamp.ko.md) 문서에 구분해 기록한다.
