# 웹 기록 전송 상태 (1.9.0)

결과 화면 하단에 해당 플레이의 웹 전송 상태를 표시한다. 요약·분석·멀티 결과 화면에서 동일하게 보이며, F10 웹 리더보드 탭에는 최근 전송의 구체적인 안내가 남는다. 전송이 늦게 끝나도 리플레이 SHA가 다른 다음 결과의 상태를 덮어쓰지 않는다.

기존 구현은 전송 오류를 `result.notes`에 넣었지만 결과 렌더러가 이 내용을 그리지 않았다. 이번에는 전용 표시 필드를 사용한다. 기록 등록 실패의 원인과 오류가 보이지 않았던 표시 결함은 구분해야 한다.

| 상태 | 의미 / 다음 확인 |
| --- | --- |
| 웹 미연결 | 로컬 연결 정보가 없어 전송하지 않았다. F10에서 등록한다. |
| 웹 기록 전송 중 | 현재 플레이의 전송 결과를 기다린다. |
| 웹 기록 등록 완료 | 서버가 HTTP 200/201 및 `accepted: true`로 응답했다. 중복 접수도 포함한다. |
| HTTP 400 | 기록 형식·버전·플레이 조건을 확인한다. 서버가 `future_play_time`을 반환하면 PC 날짜/시간을 안내한다. |
| HTTP 401 | 연결 키가 없거나 만료·폐기되었다. 새 연결 정보를 F10에 등록한다. |
| HTTP 403 / 404 | 사이트 접근 상태 또는 연결 주소를 확인한다. |
| HTTP 429 | 기존 제한된 재시도 후에도 요청 제한이 남은 상태다. 잠시 후 다음 플레이에서 확인한다. |
| 웹 등록 제외 | 리플레이 재생, 중단·일시정지·연습·보조 조건 등 기존 등록 제외 정책에 해당한다. |

과거 로컬 기록에는 당시 웹 전송 상태를 저장하지 않았으므로 이력 화면은 등록 여부를 추측하지 않는다. 자동 재전송, 등록 조건, 재시도 횟수, 점수/리플레이 형식과 서버 순위 식별자는 바꾸지 않는다. 등록 실패 기록의 자동 복구 기능은 추가하지 않았다.

전송 상태는 로컬에서 작성한 한영 문구만 표시한다. 임의 서버 오류 본문·키·파일 경로를 표시하지 않으며, HTTP 400에서는 허용된 오류 코드 하나만 판독한다. 로컬 연결 정보가 있다는 표시만으로 서버에서 아직 유효한 키임을 보장하지 않는다. 사이트에서 연결 정보를 재발급하면 이전 키가 즉시 해제된다.

검증 경로: `test_sites_leaderboard.cpp`의 HTTP 상태·응답 승인·오류 코드 허용목록·다른 결과 메시지 격리 검사, `menu_visual_preview --result --web-upload-status "웹 인증 실패 (HTTP 401) · F10에서 연결 정보 다시 등록 · 로컬 저장"`의 표시 검사. 실제 계정 점수 전송은 별도 확인 사항이다.
