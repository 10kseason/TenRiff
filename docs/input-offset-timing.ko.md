# 입력 보정값과 콜백 위상에 따른 판정 흔들림

## 재현된 문제

동일한 노트와 동일한 입력 타임스탬프를 실제 `GameSession::audio_callback`으로 전달하되,
48 kHz / 480프레임 콜백의 시작 위치만 0 / 2.5 / 5 / 7.5ms 바꿨다.
학습된 시계 변환은 고정하여 시계 추정 오차와 입력 보정 처리의 영향을 분리했다.

수정 전 +20ms 입력 보정은 실제 판정 델타가 +10 / +12.5 / +15 / +20ms였다.
0ms와 -20ms는 각각 일정했다. 입력 보정을 더한 시각이 현재 쓰기 버퍼 끝과 4ms
lookahead를 넘으면 버퍼 끝으로 잘라 버리는 코드가 정상적인 양수 보정도 훼손했다.
따라서 이 경로에서는 일정한 설정값이 콜백 위치에 따라 노트별로 달라질 수 있었다.

이 코드는 1.8.5에도 존재했다. 이번 재현은 결함의 존재를 확인한 것이며,
“1.8.6에서만 체감됐다”는 제보의 회귀 원인 전체를 확정한 것은 아니다.
물리 키보드·실제 음성/영상 동기 측정이나 제보자의 환경 검증을 대신하지 않는다.

## 변경과 이유

- 시계 변환과 시작 앵커로 구한 원래 입력 시각에 먼저 미래 시각 안전 경계를 적용한다.
  그 뒤 사용자 입력 보정을 더해 판정과 리플레이 기록에 그대로 전달한다.
- 라이브 키음과 합성 키 톤은 보정 전 시각 또는 현재 쓰기 버퍼 시작 중 늦은 쪽에서 시작한다.
  +200ms 보정 때문에 실제 키음도 200ms 지연시키지 않는다.
- 보정된 판정 시각을 미래 큐로 보내지 않는다. 입력은 기존 소비 순서로 즉시 판정한다.
  같은 상수를 더하므로 정상 입력의 순서는 유지되고, 엔진의 기존 단조 시각 보호도 유지된다.
- 오래된 입력의 QPC 기반 판별, 레인별 마지막 상태 따라잡기, 보조키 통합,
  자동 스크래치와의 시각순 병합, 미스 갱신은 기존 경로를 유지한다.
- `FutureQueue`는 실제 제품 코드에서 넣는 곳이 없고 기존 테스트만 사용한다.
  이번 수정은 해당 큐의 동작이나 용량을 바꾸지 않는다. 새 대기 큐·동적 할당 경로도 추가하지 않는다.

수식으로 쓰면 원래 입력 시각을 `S`, 사용자 보정을 `O`, 버퍼 끝을 `B`, lookahead를 `L`이라 할 때,
안전 보정은 `S > B + L`인 경우에만 `S = B`로 수행하며 판정 시각은 그 뒤 `S + O`로 정한다.
키음 시작 시각에는 `O`를 더하지 않는다.

## 리플레이 호환 경계

R1~R4 리플레이, 자동 연주, 고스트의 기존 이벤트 시각과 점수 계산은 변경하지 않는다.
리플레이와 자동 연주의 음원은 기존 기록/예약 시각으로 재생한다.
현재 리플레이 형식은 보정된 판정 시각만 보관하고 물리 입력 시각은 보관하지 않으므로,
입력 보정을 사용한 새 라이브 연주와 그 리플레이의 키음 시작 시각까지 동일하다고 보장하지 않는다.
이를 동일하게 만드는 형식 변경은 이번 수정에 포함하지 않는다.

## 회귀 검증 항목

`tests/unit/test_game_session_audio.cpp`의 실제 콜백 또는 실제 입력 처리 경로로 다음을 검사한다.

- 0 / ±20 / ±200ms 보정, 각 네 콜백 위치에서 판정 델타와 리플레이 샘플이 정확히 일정한지
- 같은 콜백에서 키음이 실제 믹스되고 음원 시작 시각이 보정값 때문에 밀리지 않는지
- 잘못된 미래 시각의 안전 보정이 양수/음수 입력 보정에 가려지지 않는지
- 연속 누름/뗌의 순서와 라이브 합성 톤 시각이 유지되는지
- R1~R4 리플레이와 자동 연주가 라이브 입력 보정을 다시 적용하지 않고 기존 음원 시각을 유지하는지

빌드와 실행 결과, 수정 전 실패 로그 및 전체 검증 수치는 상위 작업의 검증 보고서에 기록한다.
