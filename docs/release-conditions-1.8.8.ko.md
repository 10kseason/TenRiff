# 1.8.8 추가 조건 후보 — 이전 로컬 검증 기록

이 문서는 2026-10-12 추가 조건 후보 `e46bab7`의 요구·구현·당시 로컬 검증을 보존합니다. 범위는 **창 크기 자유 조절과 가로·세로 직접 입력**, **결과 화면의 작은 스크린샷 단축키·저장 위치 안내**, **여러 박 길이의 LN과 다른 레인의 단노트·짧은 LN이 섞이는 LN Mix**였습니다. 아래 통과 수치는 이후 화면·메뉴·키음·시작 조작을 포함한 릴리스의 새 검증 횟수가 아닙니다. 현재 상태는 [1.8.8 릴리스 안내](release-1.8.8-gate.md)를 따릅니다.

현재 고정 기준은 [1.8.7](baseline-1.8.7.md)이며 태그 `1.8.7`, 커밋 `6b060ad47b950ad9e0dbc516fbb40189e8e21347`과 기존 배포 파일을 유지합니다. 이 문서는 1.8.8 공개 릴리스 완료나 기준선 변경을 뜻하지 않습니다. 플러그인 실행 환경·API·SDK와 1.9.0 안정화는 계속 [계획](result-analysis-1.8.8.ko.md) 범위입니다.

## 이전 후보와 검증 구분

## 창 크기와 직접 해상도 입력

창 모드는 프리셋 선택 외에 사용자가 테두리를 끌어 크기를 바꿀 수 있어야 합니다. 그래픽 설정에서 가로·세로를 직접 입력하는 경로도 제공합니다. 잘못된 입력, 취소, 저장 후 재실행, 메뉴와 플레이 전환에 대한 동작을 명시하고 확인합니다.

| 조작 | 동작 |
| --- | --- |
| 해상도 `+/-` | 기존 `native`·프리셋·모니터 표시 모드 순환 |
| 해상도 항목에서 `Enter` 또는 값 클릭 | 가로·세로 입력 초안 열기 |
| 키보드 상단 숫자열 / 숫자패드 `0`~`9` | 현재 항목의 숫자 입력. 다른 문자 입력은 받지 않음 |
| `Tab` / 방향키 | 가로·세로 입력 항목 전환 |
| `Enter` | 각 축 320–8192의 숫자로 된 정수이면 적용. 잘못된 값은 오류를 표시하고 기존 설정 유지 |
| `Backspace` / `Delete` | 선택값 또는 마지막 숫자 삭제 / 현재 입력 항목 비우기 |
| `Esc` | 초안 취소 |
| 창 테두리 드래그 종료 | 실제 client 크기를 프로필에 즉시 저장 |

숫자키 입력을 사용하는 화면이므로 붙여넣기나 IME로 값을 넣는 조작은 제공하지 않습니다. 예를 들어 빈 값, `12`, `8193`은 적용하지 않고 오류를 표시합니다. 문자키가 무시되는 동작과 숫자 범위 오류는 구분합니다.

최대화·복원과 프로그램이 유발한 크기 변경은 사용자가 선택한 해상도를 덮어쓰지 않습니다. 작업 영역보다 큰 값을 직접 입력하면 선택한 `가로x세로`는 보존하고 실제 창을 작업 영역에 맞게 줄입니다. 보통은 입력 비율을 유지하지만 실제 client의 각 축 최소 320px도 적용하므로 `320x8192`처럼 극단적인 값은 실제 창 비율이 달라질 수 있습니다. DXGI 독점 전체화면이 지원하지 않는 크기는 창 모드로 복구한 뒤 축소된 실제 크기·모드를 저장합니다. 기존 프로필 토큰과 기본값은 유지합니다.

자유로운 창 크기와 내부 화면의 가로세로 비율은 별개입니다. 내용은 기존 1920×1080 비율로 표시하며 다른 비율에는 여백을 두고 클릭 좌표도 이 변환에 맞춥니다. 창 모드의 자유 크기 조절을 borderless 또는 DXGI 독점 전체화면의 동작과 혼동하지 않습니다. [설정 문서](config.md#graphics)에도 같은 조작을 안내합니다. 이 구현 설명만으로 실창·전환·저장 검증을 통과한 것으로 보지 않습니다.

## 결과 스크린샷 안내

단독 요약·분석 탭·멀티 결과 하단에 **`F9 / 스크린샷 (PNG) > screenshots/`**를 작게 표시합니다. `F9`는 현재 렌더링된 화면을 PNG로 저장하는 기존 기능을 사용합니다. 점수·분포·버튼을 가리지 않고 작은 창에서도 읽을 수 있어야 합니다. 안내가 보이는 것과 실제 파일 저장 성공은 각각 검증합니다.

저장 위치는 프로세스의 현재 작업 폴더 아래 `screenshots/`이며, 기본 실행 배치 파일을 사용하면 보통 게임 폴더입니다. 현재 작업 폴더를 확인할 수 없을 때는 기존 경로에 따라 임시 폴더 아래 `screenshots/`를 사용합니다. 파일명은 `tenriff_날짜_시각_밀리초.png` 형식입니다. 폴더 탐색기 열기나 새 저장 성공 알림 기능을 추가한 것은 아닙니다.

## LN Mix의 요구 의미

여기서 긴 LN은 여러 박 동안 누르는 노트입니다. 긴 LN을 누르는 동안 다른 레인에는 단노트나 짧은 LN이 남아 있어야 합니다. **같은 레인에 이어지는 단노트를 하나로 합치는 기능은 요청 범위가 아닙니다.** 원래 노트의 시작 시각·키음과 기존 LN을 보존하고 다음 같은 레인 노트와 겹치지 않는 길이를 사용합니다.

`LN Mix 10%~90%`는 변환 가능한 단노트 후보 중 선택할 비율입니다. 전체 채보에서 그 비율의 LN을 강제로 보장하지 않습니다. 새 변환 버전 2는 **base BPM×플레이 Rate**를 기준으로 선택된 후보에 다음 길이를 배분합니다. 개수 반올림은 기존의 최대 나머지 배분을 사용하고, 같은 채보·seed·Rate·변환 버전에서 선택과 길이를 재현합니다.

| 종류 | 목표 비율 | 목표 길이 |
| --- | --- | --- |
| 긴 LN | 60% | 2박과 4박 교대 |
| 중간 LN | 20% | 1박 |
| 짧은 LN | 20% | 1/4박과 1/2박 교대 |

후보는 최소 1/2박 길이를 확보할 수 있는 단노트이며, 다음 같은 레인 시작 전 50ms를 남겨야 합니다. 긴 목표가 들어가지 않으면 `4 → 2 → 1 → 1/2 → 1/4박` 순서로 들어가는 길이까지 낮춥니다. 따라서 고밀도 채보에서는 변환할 수 있는 노트 수와 실제 긴 LN 비율이 제한됩니다. 공간을 만들기 위해 같은 레인 노트를 삭제하거나 합치지 않습니다. 기존 LN/CN과 원본 노트의 시작 위치·키음은 보존합니다.

변환 버전 1은 이전의 8비트 60% / 16비트 20% / 24·32비트 20% 계산을 유지합니다. 과거 리플레이를 새로운 길이 정책으로 조용히 재생하지 않도록 아래 버전 경계를 적용합니다.

### 기록과 리플레이 호환성 정책

새 긴 LN Mix는 변환 버전 `long_note_mix_version: 2`를 기록합니다. 이전 형식에서 이 선택적 항목이 없으면 버전 1로 읽습니다. 리플레이에서는 `mode.long_note_mix_version`, 결과 파일에서는 최상위 `long_note_mix_version`으로 저장하며, 분석 화면에는 **긴 LN 믹스 / 이전 LN 믹스**를 구분해 표시합니다. 이 버전은 LN의 채보 변환 정책을 나타내며 본체 판정·점수 규칙을 새로 정의하지 않습니다.

새 v2 리플레이는 이 변환 버전을 지원하는 1.8.8 후보에서 재생하세요. 호환성 보존은 새 클라이언트가 이전 기록을 읽는 방향이며, 1.8.7 클라이언트에서 새 v2 리플레이를 올바르게 재생한다는 보장은 아닙니다.

버전 2는 **로컬 기록·리플레이를 허용하지만 기존 채보 단위 BEST와 Sites 업로드에는 포함하지 않습니다.** 서로 다른 변환 채보가 버전 구분 없는 기존 최고 기록이나 온라인 순위에 섞이지 않게 하기 위한 이번 후보의 제한입니다. 온라인 백엔드 변경·배포는 이번 범위가 아닙니다.

자동 고스트는 현재 변환 버전 2와 맞는 기록만 선택합니다. 사용자가 이전 버전 고스트를 명시적으로 불러오는 경우에는 양쪽을 버전 1의 채보 변환으로 맞추는 호환 경로를 사용합니다. 코드 정책·리플레이 검증기·자동 선택은 확인했지만, 명시적 구형 고스트를 실제 GameSession에서 끝까지 실행하는 검사는 하지 않았습니다. 이전 리플레이를 버전 2로 자동 변환하지 않습니다.

### 전달 패키지 검증 정책

소스 스냅샷에는 패키지 생성의 대기·성공 상태를 넣지 않습니다. 전달용 아카이브는 별도 전달 보고서에서 파일 목록·SHA-256·압축 무결성(CRC)·개인 자료 제외·추출 결과와 기존 배포 파일 보존을 확인합니다. 추출 소스의 독립 빌드 수행 여부도 그 보고서에 따로 기록합니다. 이 소스의 검사 통과만으로 아카이브 검증이나 공개 배포가 완료됐다고 해석하지 않습니다.
