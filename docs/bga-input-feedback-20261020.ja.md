# BGA・入力・選曲の追加修正（2026-10-20）

[한국어](bga-input-feedback-20261020.ko.md) · [English](bga-input-feedback-20261020.en.md) · [简体中文](bga-input-feedback-20261020.zh-CN.md)

公開版1.9.8を基にユーザーが指定した1.9.8.5リリースの動作と互換範囲を説明する。一般固定基準は1.9.6で、過去のリリース・インストール・プロファイル・譜面原本とローカル候補を保管する。公開状態とダウンロードは[1.9.8.5の範囲](release-1.9.8.5.ja.md)を参照し、新リリースの検証完了は別の証拠で確認する。

## 要求ごとの動作

| 要求 | 変更 |
| --- | --- |
| 1 | 選曲一覧の先頭から前へ進むと末尾へ、末尾から次へ進むと先頭へ移動する。検索・フィルター後の表示一覧で循環する。 |
| 2 | BGA 画像レイヤーの完全な黒 `RGB 0,0,0` を透過する。背景画像の黒と画像本来のアルファは保持する。外部 ONNX 画像処理でもレイヤーの透過マスクを保持する。 |
| 3–5 | Save Yourself と動画 BGA のローカル資料を調査する。背景とレイヤーの画像キャッシュを分離し、動画の要求時刻・既存フレーム・EOF・古い非同期結果を処理する。デコード済みフレームが次の要求時刻より先でも、それだけで巻き戻さない。 |
| 6 | FAST/SLOW は小数第1位まで表示する。絶対値を外側の 0.1ms 単位に切り上げるため、22.0208ms は `22.1 ms` となり、`22.0 ms` に隠れない。判定計算は変更しない。 |
| 7 | レーンの主キー・第2キーに Esc を割り当てられない。キャンセル・一時停止の役割は維持する。 |
| 8 | 推定 SP または明示的 7K に実際のスクラッチがない場合、新しい通常の原本プレイとライブラリでは 7K と認識する。00 のみの 16/56 は数えない。スクラッチのタップ・LN・LNOBJ・地雷があれば 7+1 を維持する。 |
| 9 | 選曲画面の「ソース」を「ライブラリ」に変更する。内部の保存名・パスは変更しない。 |
| 10 | A を押したまま同じレーンの B を新たに押すと、新しい入力を発生させて B に所有権を移す。B を離すとレーンは解除され、押したままの A は復活しない。A を離して再度押す必要がある。LN を切る偽の解除は挿入しない。 |
| 11 | ロビーのクリア表示から `GAUGE SHIFT` を省き、文字を少し大きく太くし、ゲージ段階の色と控えめなカード色を使う。保存状態と ASSIST の区別は維持する。 |

## 判定と互換性

- 固定 Normal PG は VEZ/EZ 22ms、NM 19ms、HD 15ms、VHD 10ms。Hard は Normal NM の行全体、EX は Normal VHD の行全体を再利用する。実際の窓は音声サンプル単位となる。時間窓・得点・ゲージ・R9/R10・過去の R1–R8 は変更しない。
- 18/19 によって従来 7+1 と分類された譜面を新しい 7K にするときは `11/12/13/14/15/18/19` の7位置を維持する。18/19 がなく既に 7K だった疎な譜面は、古い7レーンのリプレイに再配置を識別する情報がないため、従来の詰めた配置を維持する。明示的 8K などの配置、PMS、DP は既存の分類を維持する。8K 変換の書き出しは `#8K` を明記し、空のキーがあっても8位置を保持する。
- 新しい原本 7 レーンのリプレイは 7 レーンで、古い原本 8 レーンのリプレイは空のスクラッチを含む旧配置で復元する。明示的な実行時キー数変換と peer v7 は旧原本配置を使う。旧 8 レーンのゴーストを新しい 7 レーンに重ねない。
- リプレイのフィールド・形式・ルール ID は追加しない。第2キーへの移行では既存イベントによる `Pressed → Pressed → Released` を記録できる。この記録には更新後の検証器が必要で、公開 1.9.8 の検証器は連続 Pressed を拒否する場合がある。
- 一時停止からの再開でも入力の所有権を保持する。所有キーを停止中に離した場合、再開時に解除し、以前から押したままのキーを復活させない。停止中に初めて押したキーは再開後に離して押し直す必要があり、再同期自体は新しい打鍵判定を発生させない。
- 派生曲索引キャッシュを 20 から 21 に更新して再構築する。曲・リプレイ・記録原本は移行しない。Guest 除外、`client_submitted`、固定等級、BGA モデル非同梱、OFF／空パスの既定値を維持する。

## 調査・検証範囲

ローカル一覧には動画 358 件、映像資料を参照する譜面 1,142 件、未定義 BGA ID のある譜面 135 件がある。一覧の調査は、全曲の実時間再生が成功した証拠ではない。U_E 資料で Save Yourself の動画を確認した。現在の探索では out of sense の正確な参照動画を確保できず、その曲のちらつき再現は未確認である。

Media Foundation が最初にデコードしたフレームの表示時刻（PTS）を原点として固定し、後続フレームをその原点からの経過時間で比較する。Save Yourself で確認した 533.3333ms の開始オフセットをこの方法で補正する。初回要求が3秒以内なら先頭から順にデコードし、それ以降なら目標の1秒前からシークする。シーク結果が目標を超えた場合は動画を開き直し、順次デコードで復帰する。

フレーム間隔が30Hz要求周期の2倍を超え、次のフレームが1周期より先にある場合、その1フレームを本来の PTS まで保留する。順方向再生では最後に保持したフレームより古い PTS を破棄する。通常の24/25/30/60fps動作は維持する。EVE AVI で0秒の次の1.6秒フレームが約1.3秒早く出る問題を修正した。F13 と CLOSING は ffprobe で各1枚の符号化フレームを確認しており、EOF 後に PTS 0 のフレームを保持する動作は正常である。

同一実装の以前の候補から継承した証拠：集中ピクセル・PTS検査102/102件（初期位置62件・疎なフレーム間隔20件・時刻逆行20件）と、保留・進行・巻き戻し検査18/18件が通過した。動画358件すべての冒頭0～3秒、計29,356要求と再スタート検査358/358件が通過し、時刻逆行とタイムアウトは0件だった。全長再生の検証ではない。単体検査1,399件とネイティブ検査571件も通過した。追加した原本配置・キーモード・ランダムのリプレイ32組は R9 が対象で、R10 の同じ組を別途実行した証拠ではない。未解決参照のある譜面135件には条件分岐も含まれ、再生失敗135件を意味しない。未解決参照を飛ばす既存動作は維持する。

黒の透過は [BMS command memo の LAYER](https://hitkey.nekokan.dyndns.info/cmds.htm#LAYER) を参照した。[beatoraja BGImageProcessor 原本](https://github.com/exch-bms2/beatoraja/blob/master/src/bms/player/beatoraja/play/bga/BGImageProcessor.java) は画像テクスチャキャッシュの参考であり、TenRiff の検証証拠ではない。

1.9.8.5のビルド・パッケージ・独立再ビルド・CI・ダウンロード検証は[リリースゲート](release-1.9.8.5-gate.md)に従って別途記録し、候補の結果で代用しない。失敗も保存し、自動検査と物理入力・聴取・長時間プレイ・別PC・実2PC・任意の外部スキンを区別する。Web・DB・公開スキンエディターの展開は対象外である。
