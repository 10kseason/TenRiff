# TenRiff 1.9.3: 플레이 피드백과 외부 모델 호환

공개 1.9.2를 바탕으로 앞서 로컬에서 검증한 ONNX 및 플레이·Safetensors 변경을 포함한다. 고정 소스 기준선은 1.9.0이며 기존 태그·배포 파일·설치·프로필은 보존한다. 공개 상태·최종 커밋·다운로드는 [1.9.3 릴리스 페이지](https://github.com/10kseason/TenRiff/releases/tag/1.9.3)가 기준이다. 이 문서는 구현 범위이며 최종 검증 통과를 뜻하지 않는다.

## 플레이와 표시

- 공푸어는 체력을 깎고 POOR 수와 기존 원점수·콤보 처리에 남지만 일반·상세·구간 정확도에서는 제외한다. 실제 노트 미스와 BAD는 계속 정확도를 낮춘다. 새 기본/Hard는 R7, EX는 R8을 사용하며 과거 R1–R6 리플레이 계산과 보드 ID는 유지한다. 수치 판정창과 리플레이 형식은 바뀌지 않는다.
- 선곡 앨범 아트 오른쪽 아래에 BMS 저작 RANK를 4/3/2/1/0 → VEZ/EZ/NM/HD/VHD로 표시한다. 누락·잘못된 값은 EZ다. RANK 4는 메타데이터 표시이며 실제 판정창의 기존 Easy 대체 동작은 그대로다. 캐시 20으로 메타데이터만 다시 읽으며 원본 채보는 수정하지 않는다.
- Classic·Studio·대전 헤더에서 아티스트 옆에 빨간 레벨 공간을 확보한다. 인덱스에 없는 편집기 연습·직접 실행은 실제 실행 채보의 PLAYLEVEL을 읽는다.
- BMS 마디 길이·BPM/STOP·배속·스크롤 위치를 따르는 마디선을 노트 뒤에 표시한다. 판정·오디오 이벤트를 추가하지 않으며 osu! 마디 생성은 포함하지 않는다.
- 상시 FAST/SLOW는 마지막 실제 non-PG 글자와 위치를 유지한다. 조건부는 기존 750ms, 글자·막대 스위치는 독립이며 첫 피드백 전 임의의 FAST를 표시하지 않는다.
- 새 설정이나 설정 누락 시 불러오기는 안전이 기본이다. 저장된 빠름 선택은 유지하고 자체 LV/CR 계산은 별도 기본 OFF다.

## 외부 BGA 모델

처리 순서는 원본 이미지 → FFmpeg RGB 디블록 → 모델 고유 배율 추론 → 잔차 합성 또는 완성 이미지 사용 → 표시 영역 맞춤 → 필요한 크롭이다. 일반 ONNX는 문서화된 RGB NCHW FP32/FP16 단일 입력·단일 출력 계약 안에서 임의 텐서 이름, 고정 또는 전체 동적 공간 축, 균일한 정수 x1~x4를 지원한다. Auto는 명시적 출력 메타데이터, 옛 LunaSR2 이름 쌍, 그 외 완성 이미지 순서로 처리한다. 잔차·완성 이미지의 직접 선택이 우선하며 Auto가 픽셀 값으로 모델 의미를 알아내는 것은 아니다.

Safetensors는 선택적인 로컬 변환 경로다. 지원하는 LunaSR2 C32 R8/R12/R16 x2 또는 설치한 Spandrel의 변환 가능한 RGB x1~x4 구조를 수치 검증된 ONNX로 변환한 뒤 WinML로 처리한다. 사용자가 설치한 Python과 torch/safetensors/onnx/onnxruntime가 필요하며 다른 구조에는 Spandrel도 필요하다. 격리 작업자는 의존성 자동 설치·모델 다운로드·pickle 로드·모델이 제공한 Python 실행을 하지 않는다. 미지원 모델은 원본 표시를 유지하고 원인을 로그에 남긴다. [전체 모델 계약과 설정](../tools/onnx_upscaler/README.md)을 참고한다.

**BGA 모델 가중치는 실행·소스 패키지에 동봉하지 않는다.** 빈 모델 경로·업스케일 OFF·출력 Auto 기본값을 유지한다. 기존 NK3 키 변환 모델은 별도 기능으로 계속 포함한다. 정지 BGA와 선곡 이미지를 지원하며 영상 AI는 비활성이다. 동적 모델은 원본 크기를 쓰고 고정 모델은 패딩·문맥 타일을 사용하므로 모델별 크기·연산자·메모리 제약은 여전히 적용된다.

## 호환성과 검증 경계

승인되어 배포된 운영 리더보드 버전 19는 R7/R8을 별도 보드로 받으며 기존 기록·보드 ID·Stable 고정 등급표를 유지한다. 게스트와 출처 표시 없는 과거 기록은 영구 업로드 제외이며 나중에 Online으로 바꾸어도 기존 Guest 플레이를 승격하지 않는다. Sites는 서버 리플레이 검증이 아닌 `client_submitted`이다. 이번 게임 릴리스에 추가 웹·DB 변경은 필요하지 않다.

최종 빌드·독립 추출 소스·CI·패키지 해시·공개 재다운로드는 [릴리스 검증 절차](release-1.9.3-gate.md)를 따른다. 앞선 로컬 통과 결과는 후보 검증이다. 물리 입력·오디오, 장시간 플레이, 다른 PC, 실제 계정 운영 업로드, 실제 Spandrel 모델과 일반적인 품질·성능 보장은 별도 근거가 필요하다.
