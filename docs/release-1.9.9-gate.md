# TenRiff 1.9.9 verification gates

These are required checks, not a publication claim. The release is based on 1.9.8.5 commit `68394fb0940925e2ddbdf9b9bddc525cfd96a8ce`; KeyWeaver E comes from 1.3.0 commit `4bbf7cbece9657c41bd1fd2cc479155b575056d6`. The general fixed baseline stays 1.9.6.

- Build fresh Release targets and run NK2 E/Sites focused tests, full CTest and native menu/session checks. Verify all 100 existing-menu source/target pairs with different seeds, sample/hold/keysound safety, actual BMS fixtures and twenty saved R9/R10 replay-to-payload contracts. Check E OFF/Mirror versus random ghost initialization separately from ghost playback scoring.
- Preserve historical NK2 source behavior, source import provenance, explicit saved presets, current default algorithm, timing/grades, R1–R10 replay policies, peer v7 and Guest/custom/LNMix v2 exclusions. E uses an existing preset field and requires the new verifier.
- Run skin-editor, catalog, scene-music, FFmpeg and Safetensors checks. Record any optional unavailable comparison and all failed attempts. No rendering/layout feature is added by this release; previous 1.9.8.5 visual/media checks remain inherited evidence, not newly repeated physical play.
- Run web tests, type checking, production build and isolated local API tests using native serialized payloads. Accept 16K with separate identities, preserve 4–14K, reject 15/17K, and keep duplicate upload behavior and historical ranking data. Do not migrate the production DB or submit test accounts/scores there.
- Deploy to the existing public site without audience changes. Read back static assets and visible version/filter, plus all previous public boards/ranking payloads. Keep real user activity distinguishable from migration effects.
- Require exact-head PR and merged-main CI. Package runtime/source/checksum assets in fresh directories; check ZIP CRC, hashes, clean defaults, no private paths/credentials/media and no BGA weights. Preserve only the existing eighteen NK3 models. Construct final source from merged Git blobs, independently rebuild/test, and verify source preservation.
- Download all three draft assets and then fresh anonymous public assets for byte verification. Preserve the prior 106 release identities, 106 tags and 308 assets and all previous candidate/release files. Never replace an old release asset or move an old tag.

Physical input/IME/listening, long sessions, other PCs, arbitrary skins/charts, actual two-PC play and real-account production uploads remain outside automated verification. The leaderboard retains the client_submitted boundary; it does not execute the native replay verifier on the server. Source/runtime tests and local API acceptance must not be reported as those untested outcomes.
