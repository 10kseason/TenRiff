# TenRiff 1.8.9.6 — 입력 및 HUD 대기 개선

공개 1.8.9.5에서 이어지는 B 비교 방식의 제품 적용입니다. 이전 태그·배포본과 사용자 프로필, 고정 문서 기준 1.8.7은 보존합니다.

## 이전 동작과 변경 이유

Windows에서 입력의 약 0.9~1ms 대기와 게임 진행/HUD의 2ms `sleep_for`가 환경에 따라 약 15.6ms로 늘어나는 현상을 로컬 검사에서 관측했습니다. 렌더 프레임이 정상이어도 입력 메시지 수집이나 8ms 주기의 HUD 전달이 늦어질 수 있습니다.

각 대기 스레드가 이름 없는 고해상도 타이머 하나를 생성하고 반복 사용합니다. RawInput은 타이머뿐 아니라 메시지 도착에도 깨어나 기존 메시지 펌프로 처리합니다. 200µs 이하의 yield, 폴링 deadline, 등록 상태 확인과 종료 처리는 유지합니다. 시스템 전체 타이머 해상도·스레드 우선순위는 변경하지 않습니다.

고해상도 타이머를 만들 수 없으면 일반 타이머를 사용합니다. 타이머 설정/대기가 실패하면 일반 sleep 또는 메시지 timeout으로 복구합니다. 이런 환경에서도 실행은 가능하지만 같은 대기 정밀도를 보장하지 않습니다. OS 스케줄링 지연의 상한을 보장하는 변경도 아닙니다.

## 계약과 측정 한계

- 수치 판정 창, R1~R5 처리 정책, 입력 보정 값, 점수·게이지, 리플레이 형식과 변환 버전은 바꾸지 않습니다. 기존 프로필 값을 재작성하지 않습니다.
- RawInput의 시각은 메시지를 처리할 때 수집하므로, 더 빨리 깨어나면 기록되는 입력 시각과 실제 판정 느낌은 달라질 수 있습니다. 물리 키 스위치의 독립 시각을 측정한 것은 아닙니다.
- 오디오 콜백·믹싱과 렌더 노트 위치 계산은 변경하지 않습니다. HUD가 최신 시각을 전달하는 간격을 개선합니다. GPU/드라이버의 모든 긴 프레임을 해결하는 변경은 아닙니다.
- 비교용 A/B/C에는 같은 계측 코드가 포함돼 공개 원본과 바이너리 전체가 같지는 않았습니다. 같은 C에서도 움찔한 회차와 부드러운 회차가 있었으며, 서로 다른 수동 타건의 표준편차를 엔진 튐 감소율로 해석할 수 없습니다. 사용자가 B 방식의 우선 출시를 선택했습니다.
- 제품과 공개 소스에는 로컬 계측 버퍼·환경변수·원시 CSV·프로필·실험 실행기를 포함하지 않습니다. 새 웹 API나 배포는 필요하지 않습니다.

## 검증 범위

새 타이머의 비양수/반복 대기, 이미 확인한 메시지 및 대기 중 도착 메시지의 깨움, 이후 타이머 재설정을 회귀 검사합니다. 기존 입력 stop/restart·fallback, GameSession 시작/카운트다운/일시정지/종료, 판정·리플레이 검사를 새 Release 빌드에서 실행합니다.

소스 ZIP을 독립 추출·재빌드하고, 패키지의 파일 해시·기본 설정·개인정보 제외와 Git blob 일치를 확인합니다. 이 문서는 검사 계획과 범위이며, 실행 결과·CI·공개 다운로드 검증은 해당 릴리스 노트와 검증 보고서에 별도로 기록합니다. 장시간 물리 플레이·다른 PC·모든 오디오 장치의 체감 개선은 미확정입니다.
