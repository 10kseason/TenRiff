# 렌더 대기 보정값의 정체 복구

일시적인 Windows 타이머 지연으로 oversleep 추정치가 커지면, 남은 프레임 시간보다 보정값이 커져 타이머 대기를 계속 건너뛸 수 있었습니다. 실제 대기를 하지 않으면 새 표본도 생기지 않아 보정값이 그대로 남는 순환입니다.

새 후보는 보정값 때문에만 타이머 대기를 놓쳤고 실제 sleep 표본도 없는 경우, 마지막 측정/복구 후 100ms 이상 지났을 때 보정값을 7/8로 줄입니다. 프레임별 또는 yield 반복별로 줄이지 않습니다. 실제 타이머 및 fallback sleep의 EMA, 짧은 대기, FPS 목표, 프레임 마감 계산, VSync와 unlimited 동작을 유지합니다. 입력·판정·오디오·리플레이 코드와 설정은 변경하지 않습니다. EX 골드 및 이전 스킨/BGA 수정은 계승하며 파란 랭크 이미지는 아직 비교 시안입니다.

이 수정은 코드에서 재현한 CPU 대기 상태의 정체를 완화합니다. 실제 Discord 끊김의 원인이나 해결을 입증하지 않습니다. 타이머가 지속적으로 늦는 환경에서는 가끔 재시도하는 비용이 남습니다. 빠른 프레임별 감쇠안은 지속 지연 모델에서 회귀해 폐기했습니다. 100ms 간격은 CPU 낭비 복구와 재시도 빈도 사이의 절충입니다. 복귀 시간은 프레임 잔여 예산에 따라 달라집니다.

공유 없이 게임 중에만 커서까지 끊기는 경우에는 오버레이를 하나씩 비활성화해 동일 장면에서 비교하는 것이 우선입니다. 모듈이 로드되어 있다는 사실만으로 충돌이 확정되지는 않습니다. [Discord 공식 오버레이 안내](https://support.discord.com/hc/en-us/articles/217659737-Game-Overlay-101)도 해당 게임에서 지연이 생기면 오버레이 비활성화를 권합니다.
