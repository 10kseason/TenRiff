# TenRiff 1.9.0.2 发布反馈说明 · 2026-10-15

这是基于已发布1.9.0.1的 **1.9.0.2发布候选版**。固定基准保持 [1.9.0](baseline-1.9.0.zh-CN.md)，保留以前的发布版、安装、个人档案和原始谱面。公开状态和可下载文件仅以 [1.9.0.2发布页面](https://github.com/10kseason/TenRiff/releases/tag/1.9.0.2) 为准。[发布验证流程](release-1.9.0.2-gate.md)区分本地证据与剩余发布检查。

## 大厅与选曲显示

- 将Options显示为绿色。
- 仅在选择内置5K Aery难度表时显示绿色⑤。默认Lv和其他表省略⑤；等级保持红色，分数保持白色。不修改原始谱面或难度表数据。
- 将native选曲画面中央下方的排序/过滤和难度表选择框移到`Song Library`旁的页眉。利用腾出的中央空间增加专辑封面高度，保留最佳记录区域和页眉曲目计数。选择器、计数、记录和封面是否重叠须通过最终显示检查确认。
- 此移动和增高仅应用于默认compact布局。作者指定的native/legacy左侧、中央及页眉区域矩形保留原位置；曲目来源和记录不变。

### 已注册难度表的符号颜色

仅在注册表URL、准确符号和非空等级匹配时，对整个符号应用现有键模式颜色。数字等级仍为红色。Revive10使用`Ⓡ`符号，而非数字`10`。

| 表符号 | 键模式 | 颜色 |
| --- | --- | --- |
| `4UE` | 4K | `#FF9BC5` |
| `6UE` | 6K | `#8FB8FF` |
| `8UE` | 8K | `#FFD479` |
| `Ⓡ` (Revive10) | 10K | `#63E9F2` |

保留5K Aery的绿色⑤以及7K Aery、Stella和Satellite的既有显示。默认Lv和无法识别的自定义表不应用此配色。


## 等级搜索

在搜索框中使用以下语法。`lv`和`to`均不区分大小写，范围包含两端。

| 输入 | 包含的等级 |
| --- | --- |
| `lv:16to20` | 16及以上、20及以下 |
| `Lv:16` | 仅16 |
| `lv:19-` | 19及以下 |
| `lv:18+` | 18及以上 |

选择难度表时，使用 **当前表的等级**；默认Lv使用谱面/BMS等级。表中无等级或无法解析为数字的条目不会改用BMS等级匹配。可用空格组合普通搜索词，如`artist lv:16to20`，只显示同时符合两项条件的曲目。未完成或错误的`lv:`表达式按普通搜索词处理。 与数字等级过滤器采用相同的整数规则，因此难度表的`st18`和`18+`均按数字等级18搜索。

## 输入与音量设置

- 新建个人档案和未指定的`input.debounce_ms`默认值从8ms改为 **0ms**。本次默认值变更不会重置已保存的值；历史 **5ms → 8ms迁移仍然保留**，与新默认值分开处理。
- 音频UI中的主音量、BMS曲目、TenRiff音乐、BGM和键音这5项统一采用 **1个百分点步长（保存值0.01）**，便于细调。

| 设置 | 范围 | 新默认值 |
| --- | --- | --- |
| 主音量 `audio.volume` | 0–100% | 10% |
| BMS曲目 `audio.gameplay_volume` | 0–100% | 100% |
| TenRiff音乐 `audio.menu_music_volume` | 0–100% | 100% |
| BGM `audio.bgm_volume` | 0–200% | 100% |
| 键音 `audio.keysound_volume` | 0–200% | 100% |

保留已保存的音量和试听×0.75等现有输出倍率。详见 [配置文档](config.zh-CN.md)。

## 验证与兼容范围

在Aery ⑤、注册表符号颜色和选曲布局补充之前，开发构建与ZIP解压源码的独立构建均通过Release构建、CTest 3/3（各1,224项，integration skips 0）、编辑器35/35及native MenuApp/GameSession 307/307，含22项搜索按键处理检查。当时渲染覆盖6个fixture/360 Presents/86 geometry hit checks。这些结果不能替代下述最新native失败。

最终runtime Release构建已完成。最新画面检查通过 **24个fixture/1,440 Presents/381 geometry checks/24项表符号像素检查**，提供布局、颜色、像素和渲染存活证据。OS `native_dispatch`结果并非全部true，因此不能宣称所有OS点击或按键传递检查均已通过。

首次构建因不支持的测试诊断CAPTURE而失败，随后移除了这些诊断行。首次native搜索检查遗漏了minus键SC_0C，使用搜索专用键码比较修正后，上述最终检查通过。保留初始失败日志、原始输入和现有记录。

首次打包检查中，现有皮肤轨道数字快捷键测试失败过一次。随后在未修改测试可执行文件的情况下，定向重试、完整CTest重试和独立构建检查均通过，但 **根本原因仍未确认**。保留首次失败，不将重试成功视为间歇性问题已修复。

首次`smoke-layout`为 **305/307**。在任何回放输入前被15秒watchdog中止，记录`aborted=true`且全部判定数为0，后续claims不一致由中止结果引起。该次初始化延迟或音频时钟停滞的准确原因仍未知。仅增加诊断，timeout和assertion未变。

下一次`smoke-layout-final`为 **304/307**。时序通过（`timeout=0`、初始化14ms、运行3,492ms、`max_sample=153467`、回放验证通过），但最后按键结束捕获、顺序配置回读、同槽位辅助键推进失败。代码检查确认了一条污染路径：捕获点击刷新实时`GetAsyncKeyState`，按住的W/E/R可能抑制首次合成down，使捕获仍激活并忽略辅助点击。但当次按住的键未记录，**不能确认就是该次失败的原因**。仅在测试中停止并排空输入线程，清除按下/所有者状态后执行合成输入，结束时重启；产品代码及按住重复抑制assertion均保持不变。最终隔离重跑和独立构建检查仍待完成。

本地软件包、独立构建证据及初始失败保存在单独的evidence中。最终发布包对应关系、PR/main CI和公开资产检查遵循[发布验证流程](release-1.9.0.2-gate.md)，本文不提前标记为通过。实际公开状态以发布页面为准。内部按键dispatch和geometry检查不能代替实体输入验证；设备、延迟、长时间游玩和其他PC仍未验证。固定基准保持1.9.0。
