# TenRiff 1.9.9.6 — 인디케이터·리절트 및 라이브러리 로딩

1.9.9.6은 공개1.9.9.5에 인디케이터·리절트 개선과 곡 목록/폴더/난이도표 로딩 최적화를 더합니다. 일반 고정 기준선은 **1.9.6**입니다.

- 스킨 → HUD에 **게이지 바 가로 크기: 보통(100%) / 조금 더 크게(125%) / 크게(150%)**를 추가했습니다. Classic 바와 Studio 양옆 바는 필드 바깥 방향으로 가로만 커집니다. 채움·테두리·눈금에 같은 폭을 적용하고 프로필과 `.trskin`/`.trprofile`에 저장합니다. 이전 설정은 보통입니다.
- 바코드 인디케이터의 이전/최신 막대를 기본2×18 크기로 통일합니다. 최신 입력의 밝기, 점 모양, 색상, 수명, 위치와 확대 설정은 유지합니다.
- 리절트에서 `GAUGE SHIFT EX CLEAR`는 `EX CLEAR`로 표시합니다. 다른 게이지도 접두어만 제거하며 ASSIST 표시와 저장 상태는 유지합니다.
- 첫 유효 로컬 BEST 또는 기존 클리어 우선 순서에 따른 실질 갱신 시 `NEW Record`를 표시합니다. 같은 성적의 시간만 최신인 동률, 리플레이 재생, 과거 기록 열기, 저장 실패는 제외합니다. 기존 오토/연습/추가 노트/LN Mix 등의 기록 제외 조건은 그대로입니다.
- 난이도표 전환은 읽어 둔 곡 해시에 표만 다시 적용하여 곡 캐시와 기록/리플레이 검증의 재읽기를 줄입니다. 같은 URL의 갱신된 표는 계속 가져옵니다. 단일 폴더와 ALL SONG에 적용하며 Fast→Safe 변경, 빈 목록, 실행 중/미전달 스캔 결과는 기존 갱신 절차를 사용합니다.
- 폴더 집계 단계에서 중복 경로/파일 정보 조회를 생략하고 캐시·선택 목록의 불필요한 전체 복사를 줄입니다. F5 재검증, 취소/권한 처리와 메모리 배치 한도는 유지합니다. 표 전환은 외부 변경 파일의 새로 고침을 대신하지 않습니다.

동일 구현의 로컬 후보 합성 반복 중앙값은2,000곡/200폴더 탐색1,774→1,321ms(25.6%),10,000항목 표 적용383→103ms(73.1%)였습니다. 저장 목록 재열기234→231ms는 작은 변동으로 체감 개선을 주장하지 않습니다.3쌍을 순차 실행하고2번째 쌍의 순서를 바꿨으며, HTTP는 로컬 응답/기록 없음/OS 캐시 미초기화 조건입니다. 실제 사용자 라이브러리·디스크 콜드 캐시·서버 지연·다른PC에 대한 결과가 아닙니다. 후보 수치를 신선한 릴리스 측정으로 표시하지 않습니다.

곡 선택 후 플레이 준비는 이번 범위에서 제외했습니다. 입력/오디오/판정/점수/게이지 계산, 고정 등급 경계, 저장/리플레이 형식, R1–R10, peer v7과 기존 온라인 제외 조건은 유지합니다. 새 기록은 세션 표시 플래그이며 새 저장 필드를 추가하지 않습니다. 웹/DB/공개 스킨 에디터 배포는 없습니다.
