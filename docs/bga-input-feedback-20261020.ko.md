# BGA·입력·선곡 후속 수정 (2026-10-20)

[English](bga-input-feedback-20261020.en.md) · [日本語](bga-input-feedback-20261020.ja.md) · [简体中文](bga-input-feedback-20261020.zh-CN.md)

이 문서는 공개 1.9.8을 기반으로 사용자가 요청한 1.9.8.5 릴리스의 동작과 호환 범위를 설명한다. 일반 고정 기준선은 1.9.6이며 이전 릴리스·설치본·프로필·곡 원본과 로컬 후보를 보존한다. 공개 상태와 다운로드는 [1.9.8.5 릴리스 범위](release-1.9.8.5.ko.md)를 따르고, 새 릴리스의 검증 완료 여부는 별도 증거로 확인한다.

## 요청별 동작

| 요청 | 변경 내용 |
| --- | --- |
| 1 | 선곡 목록에서 맨 위의 이전 곡은 맨 아래로, 맨 아래의 다음 곡은 맨 위로 이동한다. 검색·필터로 표시 중인 목록을 기준으로 순환한다. |
| 2 | BGA 이미지 오버레이의 정확한 검정 `RGB 0,0,0`을 투명하게 합성한다. 기본 배경의 검정은 유지하고 원래 알파도 보존한다. 외부 ONNX 처리를 사용하는 이미지 오버레이도 투명 마스크를 유지한다. |
| 3–5 | Save Yourself와 영상 BGA 비교를 위한 로컬 자료를 조사한다. 기본·오버레이 이미지 캐시를 분리하고 영상의 요청 시각, 이전 프레임 재사용, EOF와 오래된 비동기 결과를 처리한다. 영상 한 프레임의 시각이 다음 요청보다 앞선다는 이유로 되감지 않는다. |
| 6 | FAST/SLOW는 소수점 한 자리로 표시한다. 절댓값을 바깥쪽 0.1ms 단위로 올림하므로 22.0208ms는 `22.1 ms`이며 `22.0 ms`로 숨겨지지 않는다. 이는 표시 규칙이며 판정 계산을 바꾸지 않는다. |
| 7 | 레인 기본 키와 같은 레인의 두 번째 키에 Esc를 지정할 수 없다. Esc 취소·일시정지 역할을 유지한다. |
| 8 | 추론된 SP 또는 명시된 7K에서 실제 스크래치가 없으면 새 일반 원본 플레이와 라이브러리는 7K로 인식한다. 빈 16/56 채널은 스크래치로 세지 않는다. 실제 스크래치 탭·LN·LNOBJ·지뢰는 7+1을 유지한다. |
| 9 | 선곡 로비의 “소스” 표시를 “라이브러리”로 바꾼다. 내부 저장 이름이나 파일 경로를 바꾸는 작업은 아니다. |
| 10 | A를 누른 상태에서 같은 레인의 B를 새로 누르면 B가 새 입력을 발생시키고 레인의 입력 소유권을 가져간다. B를 떼면 레인은 해제되며 여전히 눌린 A는 재입력되지 않는다. A도 떼었다가 다시 눌러야 한다. 소유권 이전 자체로 LN을 끊는 가짜 해제를 넣지 않는다. |
| 11 | 선곡 클리어 표시에서 `GAUGE SHIFT` 접두어를 감추고, 더 크고 굵은 글씨·게이지 단계 색·은은한 클리어 카드 색을 사용한다. 저장된 상태와 ASSIST 구분은 유지한다. |

## 판정과 호환 경계

- 고정 Normal PG는 VEZ/EZ 22ms, NM 19ms, HD 15ms, VHD 10ms이다. Hard는 Normal NM 전체 행, EX는 Normal VHD 전체 행을 그대로 사용한다. 실제 경계는 오디오 샘플 단위로 양자화하며, 이 변경은 시간창·점수·게이지·R9/R10 또는 과거 R1–R8을 조정하지 않는다.
- 18/19 채널로 과거 7+1로 분류되던 채보를 새 7K로 바꿀 때는 `11/12/13/14/15/18/19`의 일곱 자리를 유지한다. 18/19 없이 이미 7K였던 희소 채보는 과거 7레인 리플레이와 구별할 정보가 없으므로 기존 압축 배치를 유지한다. 명시적 8K 등 다른 배치, PMS, DP는 기존 분류를 유지한다. 8K 변환 내보내기는 `#8K`를 명시해 비어 있는 키가 있어도 8K를 유지한다.
- 새 원본 7K 리플레이는 7레인으로 재구성한다. 과거 원본 8레인 리플레이는 기존 빈 스크래치 자리를 복원한다. 명시적 런타임 키수 변환과 peer v7은 기존 원본 매핑을 사용한다. 과거 8레인 고스트를 새 7레인 플레이에 겹치지 않는다.
- 리플레이 필드·포맷·규칙 ID는 추가하지 않는다. 보조키 이전은 기존 이벤트로 `Pressed → Pressed → Released`를 기록할 수 있다. 이 기록을 검증하려면 1.9.8.5 검증기가 필요하며, 1.9.8 검증기는 연속 Pressed를 거부할 수 있다.
- 일시정지 후에도 기존 입력 소유권을 유지한다. 소유 키를 정지 중에 뗐다면 재개 시 해제하며, 여전히 눌린 이전 키가 부활하지 않는다. 정지 중 처음 누른 키는 재개 후 떼었다가 다시 눌러야 입력되며, 재동기화 자체는 새 타격 판정을 만들지 않는다.
- 곡 인덱스 캐시는 20에서 21로 올려 다시 만든다. 원본 곡·리플레이·기록을 마이그레이션하지 않는다. Guest 제외와 `client_submitted` 경계, 고정 등급, BGA 모델 미동봉·OFF/빈 경로 기본값은 유지한다.

## 조사와 검증 범위

현지 조사 목록에는 영상 358개, 시각 자료를 참조하는 채보 1,142개, 정의되지 않은 BGA ID가 있는 채보 135개가 있다. 이는 자료 목록이며 1,142개 전체의 실시간 재생 통과를 뜻하지 않는다. U_E 자료에서 Save Yourself 영상을 찾았다. 현재 조사에서 out of sense의 정확한 참조 영상은 확보되지 않아 해당 곡의 깜빡임 재현은 미확인이다.

Media Foundation이 반환한 첫 디코드 프레임의 표시 시각(PTS)을 원점으로 고정하고 이후 프레임을 영상 시작부터의 경과 시간으로 비교한다. Save Yourself에서 확인된 533.3333ms 시작 오프셋을 이 방식으로 보정한다. 최초 요청 위치가 3초 이내면 처음부터 순차 디코드하고, 더 늦으면 목표보다 1초 앞에서 탐색을 시작한다. 탐색 결과가 목표를 지나치면 영상을 다시 열어 순차 디코드로 복구한다.

프레임 간격이 30Hz 요청 주기의 두 배를 넘고 다음 프레임이 한 주기보다 앞서 있으면, 그 프레임 하나를 보류해 원래 PTS에 표시한다. 순방향 재생에서는 마지막 보관 프레임보다 오래된 PTS를 버린다. 일반 24/25/30/60fps 동작은 유지한다. EVE AVI의 0초 다음 1.6초 프레임이 약 1.3초 일찍 보이던 경우를 이 방식으로 고쳤다. F13과 CLOSING은 ffprobe에서 각각 인코딩 프레임이 하나임을 확인했으므로, EOF 뒤 PTS 0 프레임 유지는 정상이다.

동일 구현을 이식한 이전 후보의 증거: 집중 픽셀·PTS 검사 102/102개(시작 위치 62개·희소 프레임 간격 20개·역행 20개), 보류·진행·되감기 검사 18/18개가 통과했다. 영상 358개 모두 초반 0~3초의 총 29,356개 요청과 재시작 검사 358/358개를 통과했으며, 시각 역행과 시간초과는 0건이다. 전체 길이 플레이 검증은 아니다. 단위 검사 1,399개와 네이티브 검사 571개도 통과했다. 추가한 소스 배치·키 모드·랜덤 리플레이 32개 조합은 R9 기준이며, R10의 동일 조합을 별도 실행한 증거는 아니다. 미해결 참조가 있는 채보 135개에는 조건부 분기도 포함되므로 재생 실패 135건을 뜻하지 않으며, 해당 참조를 건너뛰는 기존 동작은 유지한다.

검정색 레이어 합성은 [BMS command memo의 LAYER 설명](https://hitkey.nekokan.dyndns.info/cmds.htm#LAYER)을 참고했다. [beatoraja의 BGImageProcessor 원본](https://github.com/exch-bms2/beatoraja/blob/master/src/bms/player/beatoraja/play/bga/BGImageProcessor.java)은 이미지 텍스처 캐시 처리 참고이며 TenRiff 동작의 검증 증거로 취급하지 않는다.

1.9.8.5의 빌드·패키지·독립 재빌드·CI·다운로드 검증은 [릴리스 게이트](release-1.9.8.5-gate.md)에 따라 별도 기록하며, 앞서 기록한 후보 결과를 새 릴리스 결과로 대신하지 않는다. 실패를 보존하고 자동 검사와 물리 입력·청취·장시간 플레이·다른 PC·실제 2PC·임의 외부 스킨을 구분한다. 웹사이트·DB·공개 스킨 편집기 배포는 이번 범위 밖이다.
