# 1.8.1 Studio 메뉴 디자인

## 변경 의도

파스텔 면, 가는 추상 아이콘, 배경 입자와 색이 갈라지는 로고가 겹치던 메뉴를
정리했습니다. 기능을 나타내는 기호, 흰색 값, 일정한 선 굵기와 선택 표시를
우선합니다. 모양은 좌표로 설계한 오리지널 도형이며 AI 코딩 도구의 도움을
받아 제작했습니다. 외부 게임 이미지나 생성형 이미지 서비스는 사용하지 않았습니다.

## 변경 전후

| 요소 | 1.8.0 | 1.8.1 |
|---|---|---|
| 옵션 아이콘 | 12종 공용 도형, 여러 항목에 동일 기호 | 18종, 10개 옵션에 각각 다른 기능 기호 |
| 카드 색 | 항목별 파스텔 | 검정·짙은 회색, 선택 카드만 조금 밝게 |
| 카드 테두리 | 색상 강조 | 일반 회색 1px / 선택 흰색 1.35px |
| 벡터 선 굵기 | 1.6 | 2.16, 35% 증가 |
| 카드 모서리 | 18px | 7px |
| 값 글자 | 항목별 파스텔 | 흰색, 미선택 설명과 아이콘은 회색 |
| 선택 | 겹친 테두리 | 얇은 흰 테두리와 밝은 아이콘 |
| 배경·로고 | 이동 입자·대각선, 색 분리·글리치 | 정돈된 배경, 로고 밑줄 움직임 |
| 홈 배경 | 분홍·보라 다면체 그림 | 검정 악기 패널과 낮은 대비의 박자 눈금 |
| 곡 선택 로비 | 임시 자켓·패널 테두리의 파스텔 | 단색 임시 자켓과 중립색 패널, 실제 곡 이미지는 표시 |

초기의 35% 색 농도 조절안은 사용자가 제공한 올블랙 참고 이미지 방향으로
대체했습니다. 벡터 선 굵기는 1.6에서 2.16으로 35% 키웠으며, 체감 가독성을
수치로 측정했다는 의미는 아닙니다. 기존 타이틀 그림 파일은 보관합니다.

## 옵션별 도움말과 키 테스트

공통 안내를 모든 화면에 반복하던 대신 선택한 옵션의 효과와 조작법을 보여줍니다.
오디오·그래픽·입력·타이밍·스킨·프로필·모드·키 설정에 한국어/영어/일본어
설명을 넣었습니다. 번역된 이름이나 화면상의 순서 대신 안정적인 옵션 ID로
설명을 찾아, 옵션 순서가 바뀌어도 엉뚱한 팁이 붙지 않도록 했습니다.
스킨 가져오기/저장 상태와 현재 입력 장치 안내도 유지합니다.

키 입력 테스트에서 **←**는 더 적은 키, **→**는 더 많은 키를 선택합니다.
순서는 4K–10K, 12K, 14K, 16K이며 양 끝에서 멈춥니다. 각 배치의 기존
기본·보조 키로 테스트하고, 저장된 바인딩이나 플레이 모드를 바꾸지 않습니다.

## 기록 창의 GPT 사이트 리더보드

- 기록 화면에서 **Tab**: 로컬 기록 → GPT 사이트 웹 순위 → 기존 검증 서버 → 로컬.
- 웹 순위의 **←/→**: 해당 곡의 키 수·Rate·룰셋·게이지·랜덤·MOD 조건 묶음 선택.
- **위/아래**: 플레이어 선택, **F5**: 새로고침, **Backspace**: 뒤로.
- 공개 `/api/boards?q=...`와 `/api/leaderboard?board=...`만 읽습니다.
  로그인·연결 파일·업로드 키 없이 조회하며, 메뉴 스레드에서 HTTP를 실행하지 않습니다.
- 사이트의 제목·조건별 묶음을 그대로 사용합니다. 변환된 차트가 함께 묶일 수 있고,
  사이트 API는 최근 최대 100개 조건과 각 조건의 상위 100명을 반환합니다.
  같은 제목만 표시하고 차트 해시가 일치하는 묶음을 먼저 배치합니다.
- 웹 기록은 `WEB`으로 표시합니다. 기존 서버의 `ONLINE VERIFIED`와 구분하며,
  웹 조회로 새 리플레이 검증을 했다고 표시하지 않습니다.
- 응답 크기 1MiB, 시간 제한, 순위·수치·문자열 검사 및 요청 교체 후 오래된 응답
  무시를 적용합니다. 연결 실패/빈 목록을 명시하고 로컬 점수를 웹 순위로 표시하지 않습니다.

## 에셋과 스킨 연결

- 원본: `tools/generate_native_menu_assets.py`의 100×100 좌표.
- 편집용 SVG: `assets/native-menu/`. 컴파일용 동일 도형: `src/render/NativeMenuAssets.h`.
- 기본 메뉴는 컴파일된 벡터를 한 번 생성·캐시해 사용합니다.
- `skins/TenRiff_Studio/skin.json`은 `native.assets` 18개 슬롯을 동봉된
  `assets/*.png`와 연결합니다. 투명 PNG는 256×256이며 따로 교체할 수 있습니다.
- 새 홈 배경은 `assets/menu/title-studio.png`이며 스킨 폴더에도 동일한
  `assets/studio-backdrop.png`를 동봉합니다. 1920×1080의 평면 도형으로 구성했습니다.
- Options → Skins에서 **TenRiff Studio**를 선택합니다. 메뉴만 정의하는 스킨이며
  플레이는 기본 렌더링을 사용합니다. 기존 사용자 스킨을 선택하면 해당 스킨의
  명시적인 색상·이미지 설정이 우선합니다.
- 키 모드 `keys`, 키 설정 `keymap`, 스킨 `skin`, 레이턴시 `latency`, 프로필
  `profile`, 키 테스트 `keytest` 슬롯을 추가했습니다. 기존 슬롯 이름은 유지합니다.
- 새 농도·선 굵기·모서리는 `native.metrics`의 `options_grid.*` 및
  `icon.stroke_width`에서 편집합니다. 색상은 `options.*`, 값은 `options.value`,
  일반 테두리는 `options.border`에서 편집합니다. PNG 선 굵기는 이미지 자체에
  들어 있으므로 `icon.stroke_width`는 컴파일된 벡터에만 적용됩니다.

새 파일 형식이나 실행 중 추가 라이브러리는 없습니다. PNG를 다시 만드는
개발 도구만 기존 스킨 제작 도구와 같은 Pillow를 사용합니다.

스킨 연결 검사에서 기존 글꼴 초기화 버그도 재현했습니다. Native 수치 설정이
있는 스킨을 열면 글꼴 역할 표를 만들면서 `ComPtr`의 `operator&`가 다른 글꼴까지
해제했습니다. 객체를 해제하지 않는 `std::addressof`로 바꿨습니다. 새 색 농도
설정에는 1 미만 값을 허용하고, 현재 화면에 필요한 이미지 역할만 미리 읽어
24개 이미지 캐시 안에서 유지합니다.

## 재현과 검증

```text
python tools/generate_native_menu_assets.py --check
python skins/TenRiff_Studio/generate.py --check
python tools/native_skin_catalog.py --check
node tools/skin_editor/test_core.cjs
```

로컬 후보의 실제 빌드·CTest·렌더 캡처 결과는 별도 배포 폴더의
`evidence/VERIFICATION-r2.ko.md`에 기록합니다. 렌더 도구는 생산 D3D11/D2D 코드와
클릭 좌표 해석기를 호출합니다. 이것이 실사용자의 마우스 입력, 장시간 플레이,
다른 PC 성능이나 디자인 선호를 검증하는 것은 아닙니다. 공개 배포의 검증 범위는
[1.8.1 릴리즈 문서](release-1.8.1-gate.md)와 GitHub 릴리즈 노트에 기록합니다.
