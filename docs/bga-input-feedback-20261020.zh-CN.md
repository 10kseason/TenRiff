# BGA、输入与选曲后续修正（2026-10-20）

[한국어](bga-input-feedback-20261020.ko.md) · [English](bga-input-feedback-20261020.en.md) · [日本語](bga-input-feedback-20261020.ja.md)

本文描述用户指定、基于已发布1.9.8的1.9.8.5版本行为和兼容范围。通用固定基线仍为1.9.6，保留旧版本、安装目录、配置、谱面原件和本地候选版本。发布状态与下载见[1.9.8.5发布范围](release-1.9.8.5.zh-CN.md)，新版本验证完成情况另行记录。

## 各项请求

| 请求 | 变化 |
| --- | --- |
| 1 | 选曲列表顶部向前移动会到末尾，末尾向后移动会到顶部。循环范围是当前搜索和筛选后的可见列表。 |
| 2 | BGA 图片叠加层的纯黑 `RGB 0,0,0` 变为透明。保留基础背景的黑色与原有 alpha。可选外部 ONNX 图片处理也保留叠加层透明遮罩。 |
| 3–5 | 调查本地 Save Yourself 与视频 BGA 素材。分离基础层与叠加层图片缓存，处理视频请求时钟、已有帧、EOF 和过期异步结果。解码帧时间领先于下次请求时，不因此倒退播放。 |
| 6 | FAST/SLOW 显示一位小数。绝对值向外按 0.1ms 进位：22.0208ms 显示 `22.1 ms`，不会显示为 `22.0 ms`。只改变显示，不修改判定计算。 |
| 7 | 主键和同一轨道的第二按键均不可绑定 Esc。保留 Esc 的取消与暂停作用。 |
| 8 | 推断的 SP 或明确声明的 7K 如果没有实际划盘对象，新普通原谱游玩和曲库将识别为 7K。只有 00 的 16/56 行不算划盘；实际划盘单键、LN、LNOBJ 和地雷仍保留 7+1。 |
| 9 | 选曲大厅的“来源”改为“曲库”。内部存储名称和路径不变。 |
| 10 | 按住 A 时新按下同轨道 B，会产生新输入并将控制权交给 B。松开 B 后轨道释放，仍按住的 A 不会再次触发；必须先松开 A 再按下。控制权转移不插入会打断 LN 的虚假释放。 |
| 11 | 大厅通关文字隐藏 `GAUGE SHIFT` 前缀，适当增大加粗，使用对应血条等级颜色并给卡片加淡淡的通关色。保留存储状态与 ASSIST 区别。 |

## 判定与兼容边界

- 固定 Normal PG 仍为 VEZ/EZ 22ms、NM 19ms、HD 15ms、VHD 10ms。Hard 复用完整 Normal NM 行，EX 复用完整 Normal VHD 行。实际窗口按音频采样量化。时间窗、分数、血条、R9/R10 和历史 R1–R8 均不调整。
- 通过 18/19 通道在旧版被归类为 7+1 的谱面改为新原谱 7K 时，保留 `11/12/13/14/15/18/19` 七个位置。没有 18/19 且旧版已识别为 7K 的稀疏谱面保留原压缩映射，因为旧七轨回放没有区分重新映射的信息。明确声明的 8K 等其他布局、PMS、DP 保持原分类。8K 转换导出明确写入 `#8K`，即使部分按键为空也保留八个位置。
- 新原谱 7 轨回放重建七轨；历史原谱 8 轨回放恢复空划盘位置。明确的运行时键数转换与 peer v7 保留旧原谱映射。不会把旧 8 轨影子叠加到新 7 轨游玩上。
- 不添加回放字段、格式版本或规则 ID。第二按键接管可用现有事件记录 `Pressed → Pressed → Released`。这种回放需要更新后的验证器，已发布 1.9.8 的验证器可能拒绝连续 Pressed。
- 暂停后恢复时保留输入控制权。暂停中松开控制键会在恢复时释放轨道，不让之前仍按住的旧键重新生效。暂停中首次按下的键需要恢复后先松开再按下；重新同步本身不产生新打击判定。
- 派生曲库索引缓存从 20 升至 21 并重建一次，不迁移谱面、记录或回放原件。保留 Guest 排除、`client_submitted` 边界、固定等级、不附带 BGA 模型和 OFF／空路径默认值。

## 调查与验证范围

本地清单包含 358 个视频、1,142 个引用视觉素材的谱面及 135 个包含未定义 BGA ID 的谱面。清单覆盖不代表全部谱面已通过实时无闪烁播放验证。已在 U_E 素材中找到 Save Yourself 视频。当前搜索没有找到 out of sense 对应的确切视频，该曲闪烁的直接复现仍未验证。

以 Media Foundation 首个解码帧的显示时间戳（PTS）作为固定原点，后续帧按相对原点的经过时间进行比较。这修正了 Save Yourself 中观察到的 533.3333ms 起始偏移。首次请求位置不超过3秒时从开头顺序解码；更晚的位置从目标前1秒开始定位。若定位结果越过目标，则重新打开视频并恢复顺序解码。

帧间隔超过30Hz请求周期的两倍且下一帧领先超过一个周期时，暂存这一帧，直到其原始 PTS 再显示。正向播放时丢弃 PTS 早于上一保留帧的帧。保留普通24/25/30/60fps行为。这修正了 EVE AVI 在0秒帧之后，将1.6秒帧提前约1.3秒显示的问题。ffprobe 确认 F13 和 CLOSING 各只有一个编码帧，因此 EOF 后保留 PTS 0 帧属于正常行为。

继承自相同候选实现的证据：集中像素／PTS检查102/102项通过（初始位置62项、稀疏帧间隔20项、时间戳倒退20项），暂存／前进／回退检查18/18项通过。全部358个视频通过开头0～3秒的共29,356次请求和358/358项重启检查，时间戳倒退及超时均为0。这不代表验证了完整时长播放。1,399项单元测试及571项原生检查也通过。新增原谱布局、键数模式和随机模式回放的32种组合针对 R9，不代表另行执行了 R10 下相同的组合。存在未解析引用的135个谱面包含条件分支，并不代表135个已确认的播放失败；跳过未解析引用的原有行为不变。

黑色透明叠加参考 [BMS command memo 的 LAYER](https://hitkey.nekokan.dyndns.info/cmds.htm#LAYER)。[beatoraja BGImageProcessor 原始代码](https://github.com/exch-bms2/beatoraja/blob/master/src/bms/player/beatoraja/play/bga/BGImageProcessor.java) 仅供图片纹理缓存实现参考，不作为 TenRiff 验证证据。

1.9.8.5的构建、打包、独立重建、CI和下载验证依照[发布检查](release-1.9.8.5-gate.md)另行记录，不以候选结果代替。保留失败，并区分自动检查与物理输入／听音、长时间游玩、其他电脑、真实双机和任意外部皮肤验证。网站、数据库和公开皮肤编辑器部署不在本次范围内。
