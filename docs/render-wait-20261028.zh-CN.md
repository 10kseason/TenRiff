# 恢复停滞的渲染等待补偿

临时定时器延迟可能使 oversleep 估计值过大，导致后续定时器等待一直被跳过。没有新的等待样本时，原估计值会长期保持不变。

仅当补偿值阻止等待且本次没有实际 sleep，并且距上次测量或恢复至少100ms时，才将估计值衰减至7/8。不会每帧或每次 yield 都衰减。实际样本EMA、短等待、目标FPS、帧截止时间、VSync及无限模式保持原行为。输入、判定、音频、回放代码和设置不变。继承此前金色、皮肤及BGA修正；蓝色等级图片仍为设计方案。

此修改针对代码中可复现的等待状态，不证明Discord卡顿的根因或实际修复效果。定时器持续延迟时仍有少量重试开销。逐帧衰减方案在持续延迟模型中出现回归，因此采用100ms间隔限制重试频率。恢复时间取决于剩余帧预算。

未共享屏幕但游戏中光标仍卡顿时，可在同一场景逐个关闭叠加层进行比较。模块已加载不代表已确定冲突。[Discord官方叠加层指南](https://support.discord.com/hc/en-us/articles/217659737-Game-Overlay-101)。
