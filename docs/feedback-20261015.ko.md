# TenRiff 1.9.0.1 피드백 수정 · 2026-10-15

1.9.0 위에 적용한 1.9.0.1 변경이다. 고정 기준선은 1.9.0이며 이전 설치·프로필·채보·공개 자산을 보존한다. 패키지·공개 검증은 [릴리스 검증 범위](release-1.9.0.1-gate.md)와 버전별 릴리스 기록을 따른다.

- 곡 미리듣기 최종 게인에 0.75를 곱한다. 곡 선택 변경, 음량 변경, 포커스 복귀에도 같은 감쇄를 적용한다. 인게임 BMS·키음·편집기 시청과 텐리프 자체 음악 0.1 감쇄는 그대로다.
- 프로필에 `배속 -10 키`, `배속 +10 키`를 추가했다. 기본 F5/F6은 절반/두 배에서 -10/+10으로 바뀐다. F3/F4의 ±0.25, 범위 0.50–50.00은 유지한다. 누르고 있는 동안 중복 실행하지 않으며 게임·초기 카운트다운·일시정지에 적용한다. 재개 카운트다운에서는 기존 조작 잠금을 유지한다.
- Enter/클릭으로 키 지정을 시작하고 Esc로 취소, Delete로 해제한다. 레인·다른 조절 키·재시작·예약 키 충돌을 거부한다. `ui.hispeed_decrease_key`, `ui.hispeed_increase_key`에 저장하며 `.trprofile`에도 포함한다. 예전 설정에 항목이 없으면 F5/F6을 사용하고, 직접 편집·가져오기로 충돌한 키는 해당 곡에서 비활성화한다.
- 프로필 사진·곡 폴더·스킨·모델·설정 가져오기/내보내기·편집기 저장·계정 연결 파일 선택은 공통 모달 처리를 사용한다. 현재 프로세스의 창을 부모로 지정하고 중첩 호출을 막으며, 닫을 때 대기 중인 키·클릭·문자·반복 상태를 비운다. 닫기 키는 뗀 뒤 새로 눌러야 메뉴에서 작동한다.

## Xbox/XInput 게임패드

Windows 시스템의 XInput 1.4를 사용하고, 사용할 수 없으면 9.1.0을 시도한다. 별도 DLL을 배포하지 않는다. XInput 시스템 조회는 전용 작업 스레드가 맡아 키보드 입력 수집을 막지 않게 하고, 기존 InputThread가 내부 큐를 받아 RawInput·Polling 양쪽의 공통 입력 큐로 전달한다. 작업 스레드는 입력 시작·종료에 맞춰 생성·정리하며 상시 서비스로 설치하지 않는다. 키 설정에서 버튼을 눌러 레인에 지정하거나 프로필에서 재시작·배속 키로 지정한다. 저장 이름은 `PadUp`, `PadDown`, `PadLeft`, `PadRight`, `PadStart`, `PadBack`, `PadLS`, `PadRS`, `PadLB`, `PadRB`, `PadA`, `PadB`, `PadX`, `PadY`, `PadLT`, `PadRT`이다. LS/RS는 스틱 클릭이며 스틱 축은 지원하지 않는다. LT/RT는 30/255를 초과할 때 눌림으로 처리한다.

최대 네 패드의 같은 버튼은 하나의 논리 입력으로 합친다. 모두 놓아야 해제되며 연결 해제 시 해당 패드의 눌림을 제거한다. 연결·포커스 복귀 때 이미 누른 버튼은 놓은 뒤 다시 눌러야 한다. 연결되지 않은 슬롯은 2초 간격으로 다시 확인한다. 메뉴는 방향 패드로 이동, A로 선택, B로 돌아간다. 플레이에서 다른 조작에 지정하지 않은 Start는 일시정지다. 기존 키보드 설정은 유지하며, 아날로그 스틱 축·진동은 포함하지 않는다.

구현과 모의 입력 검증은 실제 Xbox 패드의 연결·버튼·물리 지연 검증과 구분한다. 실제 패드와 다른 PC 동작은 별도로 확인해야 한다.

## DEATH_SENTENCE 진단과 수정

제보 파일의 문제 구간에는 투명 노트 채널 3x/4x가 없고 D1–D5 지뢰 32개가 있다. 지뢰를 일반 노트로 바꾸거나 삭제하지 않는다. 일반 노트 뒤 급변속에 들어가기 전에 BPM 186 복귀와 STOP 48이 같은 위치에 있다.

기존 정규화는 같은 위치에서 데이터 분할 수로 이벤트 순서를 정했다. STOP의 분할 수가 더 작아 BPM 65,535.9999로 정지를 먼저 계산했고, 322.580645ms여야 할 정지가 약 0.915527ms가 됐다. 48kHz에서 이후 일정은 15,440샘플(321.666667ms) 당겨졌다. 2번 레인의 일반 노트와 첫 같은 레인 지뢰의 간격은 약 15.5625ms였으며 수정 후 약 337.229167ms다. 이 때문에 정상적인 짧은 탭이 지뢰를 누른 상태로 처리될 수 있었다.

같은 위치의 소리/노트 시각은 유지하고, 그 위치의 BPM을 모두 적용한 뒤 STOP 시간을 계산한다. [처리 순서 명세](https://bmson-spec.readthedocs.io/en/master/doc/index.html#order-of-processing)도 BPM 다음 STOP을 명시한다. 원본의 극단적인 BPM·순간 이동 연출과 지뢰 피해는 보존한다. 음악 재생 Rate는 노트·음원·STOP 시각을 함께 스케일하고, Hi-Speed는 시각 배율만 조절한다.

## 기록 호환성

사용자 승인으로 리플레이의 `mode.bms_timing_version`, 결과의 `bms_timing_version`을 선택적으로 추가했다. 생략/1은 기존 순서, 2는 수정된 순서이며 다른 값은 거부한다. 리플레이 형식 3과 R1–R6 점수/판정 규칙은 변경하지 않는다. 이전 리플레이는 원래 순서로 재생·검증하며, 수정의 영향을 받는 채보의 새 플레이만 버전 2를 내보낸다. 영향이 없는 곡은 기존 식별자를 유지한다.

한 필드의 새 플레이와 다른 시각을 가진 옛 고스트는 함께 표시하지 않는다. 옛 리플레이 단독 재생은 유지한다. 영향받는 곡의 BEST는 처음 검증된 버전 2 기록부터 새로 비교하며, 버전 1 기록은 이력에 남는다. 기존 웹 랭킹은 두 타이밍을 구분하지 않으므로 **영향받는 버전 2 기록은 웹 지원 전까지 로컬 저장**으로 표시하고 업로드하지 않는다. 웹/API/DB 배포는 포함하지 않는다. 옛 클라이언트의 버전 2 재생·검증은 지원하지 않는다.

곡 캐시는 18로 올려 이전에 계산한 길이·난이도를 다시 읽게 한다. 원본 채보와 과거 기록을 다시 저장하지 않는다. 검증 수치·실행 범위·남은 물리 입력/가청 음성/장시간 플레이 한계는 버전별 릴리스 기록과 별도 검증 자료에 기록한다. 이전 단계의 통과 수치는 최종 1.9.0.1 전체 검증을 대신하지 않는다.
