# TenRiff 1.9.0.1 feedback fixes · 2026-10-15

These changes target 1.9.0.1 on top of 1.9.0. The pinned baseline remains 1.9.0; previous installations, profiles, charts and published assets are preserved. Package/publication evidence follows the [release gate](release-1.9.0.1-gate.md) and version-specific release notes.

- Song previews multiply their final gain by 0.75, including volume changes and focus restoration. Gameplay audio and TenRiff scene music keep their existing gains.
- Profile now assigns Hi-Speed -10/+10 keys, default F5/F6, replacing half/double. F3/F4 remain ±0.25; range remains 0.50–50.00. A held key acts once. Enter/click begins capture, Esc cancels, Delete clears. Conflicting lane, restart, reserved and other control keys are rejected. The settings `ui.hispeed_decrease_key` and `ui.hispeed_increase_key` are saved in profiles and .trprofile exports.
- File pickers use an owned modal window, reject nested opening and discard queued menu input on close. A key held when closing must be released before it can activate the menu again.

## Xbox/XInput gamepads

Use Windows' system XInput 1.4, falling back to 9.1.0 if unavailable. No extra DLL is bundled. A dedicated worker performs XInput system calls so they do not block keyboard capture; the existing InputThread drains its internal queue into the shared input queue for both RawInput and Polling. The worker starts and stops with input collection and is not installed as an always-running service. Press a button in Keymap to bind a lane, or in Profile to assign restart/Hi-Speed. Saved names are `PadUp`, `PadDown`, `PadLeft`, `PadRight`, `PadStart`, `PadBack`, `PadLS`, `PadRS`, `PadLB`, `PadRB`, `PadA`, `PadB`, `PadX`, `PadY`, `PadLT`, `PadRT`. LS/RS mean stick clicks, not axes. LT/RT count as pressed above 30/255.

Up to four controllers share logical button bindings: a button releases only after every controller releases it, and disconnecting clears that controller's hold. Buttons already held at connection or focus restoration must be released before pressing again. Empty slots are rescanned every two seconds. Menus use D-pad navigation, A to select and B to return; otherwise unassigned Start pauses gameplay. Existing keyboard bindings remain. Analog stick axes and vibration are outside this release.

Implementation and simulated input checks are separate from physical Xbox-device connection, button and latency testing. Physical controllers and other PCs still require separate verification.

## DEATH_SENTENCE

The reported chart contains 32 D1–D5 mines and no invisible-note 3x/4x channels. At a shared BPM 186 / STOP 48 position, storage ordering previously calculated STOP with the preceding BPM 65,535.9999: 0.915527 ms instead of 322.580645 ms. At 48 kHz this pulled later events forward by 15,440 samples. The lane-2 tap to mine gap was 15.5625 ms; corrected it is 337.229167 ms. A short ordinary tap could therefore detonate a mine.

The correction applies all coincident BPM changes before calculating STOP, retaining note/audio time at the position and the authored extreme BPM and mines. Rate scales the complete chart/audio timeline; Hi-Speed changes visual scale. See the [processing order specification](https://bmson-spec.readthedocs.io/en/master/doc/index.html#order-of-processing).

## Compatibility

Optional replay `mode.bms_timing_version` and result `bms_timing_version`: absent/1 preserves historical scheduling; 2 uses corrected scheduling; other values are rejected. Replay format 3 and R1–R6 scoring stay unchanged. Only affected new plays export 2. Old replays play and verify with their original timing. A mismatched old ghost is excluded on affected charts. The first verified corrected score starts the corrected chart BEST; older scores remain in history.

The existing web leaderboard cannot distinguish the schedules, so affected v2 scores stay local with an explicit status until web support is added. Unaffected charts retain existing upload behavior. No web/API/database deployment is included; old clients do not support corrected-v2 replay playback. Cache version 18 refreshes chart length/difficulty without rewriting charts or old records.

Version-specific release notes and separate evidence record build/test/runtime results and remaining physical-input, audible-output and long-play limits. Earlier intermediate passes do not establish final 1.9.0.1 validation.
