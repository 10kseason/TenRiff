# TenRiff 1.9.0.2 リリース案内 · 2026-10-15

公開済み1.9.0.1に基づく **1.9.0.2リリース候補** です。固定基準は [1.9.0](baseline-1.9.0.ja.md) で、過去の公開版・インストール・プロフィール・元の譜面を保全します。公開状況とダウンロードは [1.9.0.2リリースページ](https://github.com/10kseason/TenRiff/releases/tag/1.9.0.2) のみを基準に確認してください。[リリース検証手順](release-1.9.0.2-gate.md)はローカル根拠と残る公開確認を区別します。

## ロビーと選曲表示

- Optionsを緑色で表示します。
- 組み込み5K Aery難易度表を選択したときだけ緑の⑤を表示します。既定Lvと他の表では⑤を省略し、レベルは赤・スコアは白を維持します。元の譜面と難易度表データは変更しません。
- native選曲画面の中央下にある並び替え・フィルターと難易度表の選択欄を、`Song Library`横のヘッダーへ移します。空いた中央スペースでアルバム画像の高さを広げ、ベスト記録欄とヘッダーの曲数表示を維持します。選択欄・曲数・記録・画像が重ならないことは最終描画確認の対象です。
- この移動・拡大は既定のcompact配置に適用します。作者が指定したnative/legacyの左・中央・ヘッダー領域の矩形は従来の配置を維持し、曲ソースと記録も変更しません。

### 登録難易度表の記号色

登録表のURLと正確な記号が一致し、レベルがある場合に限り、記号全体へ既存のキーモード色を適用します。数値レベルは赤のままです。Revive10の記号は数字の`10`ではなく`Ⓡ`です。

| 表の記号 | キーモード | 色 |
| --- | --- | --- |
| `4UE` | 4K | `#FF9BC5` |
| `6UE` | 6K | `#8FB8FF` |
| `8UE` | 8K | `#FFD479` |
| `Ⓡ` (Revive10) | 10K | `#63E9F2` |

5K Aeryの緑の⑤と7K Aery・Stella・Satelliteの従来表示は維持します。既定Lvと識別できないカスタム表にはこの色分けを適用しません。


## レベル検索

検索欄で以下の式を使用できます。`lv` と `to` は大文字・小文字を区別せず、範囲は両端を含みます。

| 入力 | 対象レベル |
| --- | --- |
| `lv:16to20` | 16以上20以下 |
| `Lv:16` | 16のみ |
| `lv:19-` | 19以下 |
| `lv:18+` | 18以上 |

難易度表を選択している場合は **その表のレベル** を使います。既定Lvでは譜面/BMSレベルを使います。表に等級がない項目や数値として解釈できない項目をBMSレベルで代用しません。`artist lv:16to20` のように通常の検索語と空白で組み合わせると、両方の条件に一致する曲を表示します。未完成・不正な `lv:` 式は通常の検索語として扱います。 数値レベルフィルターと同じ整数基準を使うため、表の`st18`と`18+`はどちらも数値18として検索します。

## 入力と音量設定

- 新規プロフィールおよび未指定の `input.debounce_ms` の既定値を8msから **0ms** に変更します。今回の既定値変更で保存済みの値を初期化しません。ただし従来の **5ms → 8ms 移行処理は維持**し、新規既定値と分離します。
- オーディオUIのマスター・BMS曲・TenRiff音楽・BGM・キー音の5つすべてを **1パーセントポイント刻み（保存値0.01）** で細かく調整できます。

| 設定 | 範囲 | 新規既定値 |
| --- | --- | --- |
| マスター `audio.volume` | 0〜100% | 10% |
| BMS曲 `audio.gameplay_volume` | 0〜100% | 100% |
| TenRiff音楽 `audio.menu_music_volume` | 0〜100% | 100% |
| BGM `audio.bgm_volume` | 0〜200% | 100% |
| キー音 `audio.keysound_volume` | 0〜200% | 100% |

保存済みの音量とプレビュー×0.75などの既存出力倍率は維持します。詳細は [設定文書](config.ja.md) を参照してください。

## 検証と互換範囲

Aery ⑤・登録表の記号色・選曲配置の調整前は、開発ビルドとZIP展開ソースの独立ビルドの両方でReleaseビルド、CTest 3/3（各1,224件、integration skips 0）、エディター35/35、native MenuApp/GameSession 307/307が通過しました。検索キー処理22件を含み、当時の描画は6 fixture/360 Presents/86 geometry hit checksでした。この結果で下記の最新native失敗を置き換えません。

最終runtime Releaseビルドは完了しました。最新の画面検査は **24 fixture/1,440 Presents/381 geometry checks/表記号24件のピクセル検査** を通過しました。配置・色・ピクセルと描画の稼働を示す根拠です。OSの`native_dispatch`結果はすべてtrueではなく、すべてのOSクリック・キー配送検査が通過したことは示しません。

初回ビルドは未対応のテスト診断CAPTUREで失敗し、その診断行を削除しました。初回native検索検査ではminusキーSC_0Cの認識が漏れていたため、検索専用のキーコード比較で修正し、上記の最終検査が通過しました。初期失敗ログ、元の入力と既存記録は保全します。

初回パッケージ検査では既存のスキンレーン数字ショートカット検査が一度失敗しました。同一テスト実行ファイルの変更なし再検査、CTest全体の再実行、独立ビルド検査は通過しましたが、**根本原因は未確定**です。初期失敗も保全し、再実行の成功を間欠的原因の修正とは扱いません。

初回`smoke-layout`は **305/307** でした。リプレイ入力前に15秒watchdogで中断し、`aborted=true`、全判定数0となり、後続claims不一致はその中断結果に由来します。当時の初期化遅延かオーディオ時計停止かは未確定です。診断だけを追加し、timeoutとassertionは維持しました。

次の`smoke-layout-final`は **304/307** でした。タイミングは通過しました（`timeout=0`、初期化14ms、実行3,492ms、`max_sample=153467`、リプレイ検証通過）が、最終キーのキャプチャ終了・連続プロフィール読み戻し・同一スロットの補助キー移行が失敗しました。コード確認ではキャプチャクリックが実際の`GetAsyncKeyState`を再取得するため、押されたW/E/Rが最初の合成downを抑止し、キャプチャが残って補助クリックを無視する経路を確認しました。ただし押されたキーの記録がなく、**この実行の原因とは断定できません**。製品コードを変更せず、テストのみで入力スレッド停止・キュー排出・押下/所有状態の初期化後に合成入力を実行し、終了時に再起動する分離を追加しました。押し続けたキーの反復抑止assertionは維持します。最終分離再実行と独立ビルド検査は未完了です。

ローカルパッケージ・独立ビルドの根拠と初期失敗は別のevidenceに保全します。最終公開パッケージの対応、PR/main CI、公開アセットの確認は[リリース検証手順](release-1.9.0.2-gate.md)に従い、この文書では事前に通過としません。公開状況はリリースページが基準です。内部キーdispatch・geometry検査は実機入力の検証を代替せず、実機・遅延・長時間プレイ・別PCは未検証です。固定基準は1.9.0です。
