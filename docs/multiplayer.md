# 직접 IP 멀티플레이

TenRiff의 멀티플레이는 서버 계정 없이 한 명이 호스트가 되고 다른 한 명이 IP로 접속하는 1:1 TCP 방식입니다. 기본 포트는 `27300/TCP`입니다.

## 준비 사항

- 배포 ZIP은 폴더째 완전히 압축 해제한 뒤 `launch_win.bat`로 실행합니다.
- 실행 자체가 시작되지 않는 PC는 Microsoft Visual C++ 2015-2022 Redistributable (x64)가 설치되어 있는지 확인합니다.
- 첫 실행에서 `songs` 폴더가 자동 생성됩니다. 두 PC의 `songs`에 같은 차트 폴더를 복사하거나 게임 창에 같은 폴더를 드래그 앤 드롭해 한 번 로드/인덱싱합니다.
- 두 PC에 바이트 단위로 완전히 같은 차트 파일이 있어야 합니다. 차트 전송 기능은 없으며, 헤더나 줄바꿈만 달라도 다른 차트로 판정될 수 있습니다.
- 같은 공유기 안에서는 호스트 PC의 LAN IPv4 주소를 사용합니다.
- 인터넷에서는 호스트의 공인 IP를 사용하고, 공유기에서 `27300/TCP`를 호스트 PC로 포트 포워딩해야 합니다. Windows 방화벽의 인바운드 허용도 필요할 수 있습니다.
- 통신은 암호화되거나 인증되지 않습니다. 신뢰할 수 있는 상대와만 연결하고, 채팅이나 비밀 정보를 전송하는 용도로 사용하지 마세요.

## 접속과 시작

1. 두 플레이어의 곡 라이브러리에 바이트 단위로 같은 차트 파일을 넣습니다.
2. 호스트는 TCP 포트(기본 `27300`)를 확인한 뒤 `HOST`를 선택하고 `BATTLE CHART`에서 곡을 고릅니다.
3. 참가자는 호스트의 LAN IP 또는 공인 IP와 같은 포트를 입력하고 `JOIN`을 선택합니다. 참가자 PC는 호스트가 보낸 HASH와 파일 크기로 현재 곡 폴더를 먼저 확인한 뒤, 현재 프로필에서 이전에 로드한 최근 곡 폴더의 기존 인덱스도 순서대로 확인해 같은 차트를 자동 선택합니다.
4. `HASH MATCH`와 연결 상태를 확인한 뒤 두 플레이어 모두 `READY`로 전환합니다. 준비한 상태에서 `OPTIONS`로 들어가면 Ready가 자동 해제됩니다.
5. 호스트가 `START MATCH`를 누릅니다. 양쪽 차트 로딩이 끝난 뒤 측정된 연결 왕복 지연을 보정한 시작 신호가 전달되고 게임이 시작됩니다.
6. 곡이 끝나거나 Easy 게이지가 `0%`가 되어 한쪽이 먼저 Game Over되면, 끝난 쪽은 상대의 aggregate 점수·콤보·게이지·상태를 보며 상대 플레이가 끝날 때까지 기다립니다.
7. 양쪽 플레이가 모두 종료되면 최종 결과를 서로 교환한 뒤, 내 결과와 상대 결과 및 최종 점수차가 한 화면에 표시됩니다.
8. 한쪽이 리절트를 먼저 닫아도 상대 리절트는 유지됩니다. 양쪽 모두 리절트에서 나온 뒤에 다음 선곡과 Ready가 다시 열립니다.

## 대전 규칙

공정한 비교를 위해 다음 항목은 대전 중 고정됩니다.

- Rate `1.0`, 차트 원래 키 모드
- 멀티 전용 단방향 게이지 시프트와 기본 판정 설정: `Normal`이 `33%` 이하가 되면 `Easy 100%`로 한 번 전환되고, Easy에서는 Normal로 돌아가지 않으며 `0%`에서 Game Over
- Random 및 기타 모드 수정자 끔
- Autoplay, Practice, Ghost 끔

Hi-Speed, 키맵, 스킨, 볼륨, 화면/입력/오디오 오프셋은 각 PC의 로컬 설정을 그대로 사용합니다. 플레이 중에는 상대의 점수, 콤보, 게이지와 종료/연결 상태가 HUD에 표시됩니다.

점수차 HUD는 항상 로컬 플레이어 관점입니다. 점수차 `0`은 중앙, `-10,000` 이하는 왼쪽 `LOSS` 끝단, `+10,000` 이상은 오른쪽 `WIN` 끝단에 표시되며 그 사이 값은 비례해서 이동합니다. 끝단 도달은 표시 범위를 채웠다는 뜻일 뿐, 점수차 때문에 경기가 종료되거나 결과가 확정되지는 않습니다.

한쪽이 먼저 Game Over되면 살아 있는 플레이어의 화면에는 해당 상대가 `GAME OVER`로 표시되고 플레이는 계속됩니다. Game Over된 플레이어는 상대의 aggregate 점수·콤보·게이지·진행 상태를 보며 기다립니다. 현재 protocol은 상대의 정확한 lane input이나 note별 판정/hold 상태를 전송하지 않으므로, 관전 화면은 상대 노트 필드를 추측해서 그리지 않습니다.

## 인터넷 연결이 되지 않을 때

- 호스트가 먼저 `HOST` 상태로 대기 중인지 확인합니다.
- 두 PC가 같은 TCP 포트를 쓰는지 확인합니다.
- LAN에서는 공인 IP가 아니라 호스트 PC의 LAN IPv4 주소를 사용합니다.
- 인터넷에서는 공유기의 TCP 포트 포워딩 대상 IP와 Windows 방화벽 인바운드 규칙을 확인합니다.
- CGNAT, 이중 NAT, 학교/회사망 정책 아래에서는 직접 접속이 불가능할 수 있습니다.

## 현재 범위와 제한

- 1 호스트 + 1 참가자만 지원합니다.
- 차트 파일 전송과 자동 다운로드는 지원하지 않습니다. 먼저 Game Over된 플레이어를 위한 aggregate 상태 관전은 지원하지만, 정확한 lane input/note state 기반 플레이필드 관전은 지원하지 않습니다.
- 전체 디스크나 임의 폴더를 검색하지 않습니다. 참가자 프로필의 `recent_song_sources`에 기록되고 profile-local 인덱스 캐시가 남아 있는 폴더만 검색하므로, 외부 폴더는 미리 한 번 열고 인덱싱해야 합니다.
- NAT traversal, 릴레이 서버, 매치메이킹은 지원하지 않습니다.
- 암호화, 상대 인증, 안티치트, 랭크 판정은 없습니다.
- 경기 중 자동 재접속이나 중단 지점 복구는 지원하지 않습니다.

따라서 현재 멀티플레이는 같은 차트를 이미 가진 신뢰 가능한 두 사람이 LAN 또는 직접 연결 가능한 IP 환경에서 사용하는 기능입니다.
