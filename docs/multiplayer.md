# 직접 IP 멀티플레이

TenRiff 멀티플레이는 전용 서버 계정 없이 한 PC가 방의 TCP 코디네이터가 되고, 나머지 플레이어가 그 IP로 접속하는 직접 IP 방식입니다. 방장 포함 최대 8명이며 기본 포트는 `27300/TCP`입니다.

## 준비 사항

- 모든 플레이어가 같은 protocol v5 빌드를 사용해야 합니다. 이전 protocol 버전은 handshake에서 거부됩니다.
- 멀티플레이를 포함한 전체 런타임은 BMS 계열(`.bms/.bme/.bml/.pms`) 전용이며 `.osu`는 공통곡과 후보에 들어가지 않습니다.
- 참가자 전원이 바이트 단위로 완전히 같은 BMS 차트 파일을 가지고 있어야 합니다. 헤더나 줄바꿈만 달라도 다른 차트로 판정될 수 있습니다.
- 각 PC에서 사용할 곡 폴더를 미리 한 번 열고 인덱싱합니다. 외부 폴더는 `recent_song_sources`의 profile-local 캐시가 남아 있어야 자동 매칭할 수 있습니다.
- 같은 공유기 안에서는 호스트 PC의 LAN IPv4 주소를 사용합니다.
- 인터넷에서는 호스트의 공인 IP를 사용하고 공유기에서 `27300/TCP`를 호스트 PC로 포트 포워딩해야 합니다. Windows 방화벽 인바운드 허용도 필요할 수 있습니다.
- 통신은 암호화되거나 인증되지 않습니다. 신뢰할 수 있는 사람과만 연결하세요.
- 채팅 내용도 같은 비암호화 TCP 연결로 전달되므로 비밀번호나 개인정보를 입력하지 마세요.

## 접속과 경기 흐름

1. 첫 플레이어가 포트(기본 `27300`)를 확인하고 `HOST`를 선택합니다. 이 PC는 방이 닫힐 때까지 네트워크 코디네이터로 유지됩니다.
2. 나머지 최대 7명은 호스트의 LAN 또는 공인 IP와 같은 포트를 입력하고 `JOIN`을 선택합니다. 방이 8/8이거나 경기가 진행 중이면 새 참가자는 거부됩니다.
3. protocol v5는 각 PC의 현재 indexed source에 있는 유효한 BMS SHA-256을 최대 512개씩 청크로 보냅니다. 코디네이터는 현재 참가자 전원이 가진 차트의 교집합만 공통곡으로 배포합니다. 파일 경로, 폴더명, 차트 내용 자체는 전송하지 않습니다.
4. 첫 판 선곡권자는 호스트입니다. 선곡권자는 전원 공통 BMS 목록에서 차트를 고르고, 다른 플레이어는 현재 source와 기존 `recent_song_sources` 캐시에서 hash+size가 같은 차트를 자동 선택합니다.
5. 전원이 같은 차트를 확인하고 `READY`가 되면 현재 선곡권자만 `START MATCH`를 누를 수 있습니다. 전원 chart load 완료 barrier 뒤 같은 round nonce와 시작 지연으로 경기를 시작합니다.
6. 모든 플레이어의 최종 결과가 도착하면 순위표를 표시합니다. 참가자 전원이 Result를 나간 뒤 선곡권이 입장 순서의 다음 연결된 플레이어에게 넘어갑니다.
7. 현재 선곡권자가 나가면 다음 연결 플레이어를 건너뛰지 않고 즉시 선곡권자로 지정합니다. 중간 플레이어가 나가면 빈 자리는 제거됩니다. 네트워크 호스트가 나가면 방 전체가 닫힙니다.

## 고정 경기 규칙

공정한 비교를 위해 다음 항목은 세션 동안 고정됩니다.

- Rate `1.0`; 각 PC의 로컬 키모드 변환은 허용하되 공통곡 판정은 변환 전 BMS 바이트의 SHA-256을 계속 사용
- EX-Hard / Hard / Normal / Easy를 병렬 계산하는 `Gauge Shift`; 네 tier가 모두 탈락하면 해당 플레이어가 Game Over
- 기본 판정, Random 및 기타 모드 수정자 끔
- Autoplay, Practice, Ghost 끔

Hi-Speed, 스킨, 볼륨, 화면/입력/오디오 디바이스는 각 PC의 로컬 설정을 그대로 사용합니다.

## 표시 방식

- 로비는 최대 8명의 닉네임, 본인/선곡권자, Ready 상태를 표시합니다.
- `ROOM CHAT`은 연결된 참가자의 UTF-8 메시지를 표시합니다. 메시지당 최대 256바이트, 세션당 최근 32개만 보관하고 메시지 수와 본인/리더 표식을 표시하며 파일/링크 자동 전송 기능은 없습니다.
- 플레이 중 기존 점수차 HUD는 대표 상대 한 명을 기준으로 표시합니다. 정확한 상대 lane input이나 note별 판정/hold state는 전송하지 않으므로 상대 플레이필드를 추측 렌더하지 않습니다.
- 먼저 Game Over된 플레이어는 다른 플레이어가 끝날 때까지 aggregate 상태 화면에서 기다립니다.
- Result에서는 연결된 참가자의 최종 점수를 정렬해 전체 순위를 표시합니다.

## 연결되지 않을 때

- 호스트가 먼저 `HOST` 상태로 대기 중인지, 모든 참가자가 같은 TCP 포트를 쓰는지 확인합니다.
- LAN에서는 공인 IP가 아니라 호스트 PC의 LAN IPv4 주소를 사용합니다.
- 인터넷에서는 TCP 포트 포워딩 대상 IP와 Windows 방화벽 인바운드 규칙을 확인합니다.
- CGNAT, 이중 NAT, 학교/회사망 정책 아래에서는 직접 접속이 불가능할 수 있습니다.

## 현재 범위와 제한

- 최대 인원은 호스트 포함 8명입니다. 연결 구조는 완전한 mesh가 아니라 고정 TCP 코디네이터 방식입니다.
- 곡 보유 목록은 indexed BMS의 SHA-256만 전송하지만, 상대는 특정 차트 파일 보유 여부를 hash로 비교할 수 있습니다.
- 차트 파일 전송과 자동 다운로드는 지원하지 않습니다.
- 전체 디스크나 임의 폴더를 검색하지 않습니다. profile-local 인덱스 캐시가 있는 현재/최근 source만 확인합니다.
- NAT traversal, 릴레이 서버, 매치메이킹은 지원하지 않습니다.
- 암호화, 상대 인증, 안티치트, 랭크 판정은 없습니다.
- 경기 중 자동 재접속이나 중단 지점 복구는 지원하지 않습니다.

따라서 현재 멀티플레이는 동일한 BMS 차트를 가진 신뢰 가능한 최대 8명이 LAN 또는 직접 연결 가능한 IP 환경에서 사용하는 기능입니다.
