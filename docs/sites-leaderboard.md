# TenRiff Sites 리더보드 (1.7.7 클라이언트 프로토콜)

## 설치와 사용
1. `TenRiff-1.7.7.zip`을 새 폴더에 풀고 `launch_win.bat`을 실행합니다. 실행 파일·기본 설정·런타임·스킨·키 변환 모델을 모두 포함한 전체 배포본이며 곡은 포함하지 않습니다. 기존 설치 폴더와 설정은 그대로 보관하고 곡 폴더를 게임 창으로 드래그해 연결합니다.
2. 게임에서 F10 → 리더보드 웹사이트 열기를 선택합니다. F10은 처음에 웹 리더보드 탭을 엽니다. 웹에서 ChatGPT로 로그인하고 닉네임을 정한 뒤 연결 정보 복사를 누릅니다.
3. 게임으로 돌아와 F10 → 웹 리더보드 → 연결 정보 붙여넣기(Ctrl+V)를 누릅니다. 연결 파일을 다운로드했다면 연결 파일 불러오기(Enter)로 선택해도 됩니다. config를 직접 수정하거나 파일을 옮길 필요가 없습니다.
4. 평소처럼 곡을 플레이합니다. 정상 종료 또는 게이지 실패 결과 중 지원 조건에 해당하는 기록을 백그라운드에서 전송합니다.
5. 웹에서 새로고침하고 차트를 선택해 순위를 확인합니다. 기록이 없으면 순위를 만들지 않습니다.

게임 기능은 기본 통합되어 있지만 계정 연결은 사용자가 한 번 직접 해야 합니다. 연결 전에는 기록을 업로드하지 않습니다. 기존 설치 폴더나 실행 파일을 덮어쓸 필요가 없습니다.
원래 TenRiff 서버와 공식 리플레이 검증 기능은 유지됩니다. Sites 기록은 별도의 커뮤니티 기록입니다.

## 로그인과 키
- 로그인은 OpenAI Sites가 처리합니다. 게임은 ChatGPT 비밀번호, OAuth access token, OpenAI API 키를 받지 않습니다.
- 웹은 Sites가 전달하는 이 사이트 전용 사용자 ID로 플레이어를 구분합니다. 로그인 도우미가 이메일을 읽지만 앱은 이메일을 DB에 저장하거나 순위에 표시하지 않습니다.
- 웹이 256비트 난수로 별도의 업로드 키를 만듭니다. 키는 이 사이트에 자기 기록을 제출하는 데만 사용됩니다.
- 서버에는 키의 SHA-256 해시만 저장됩니다. 원본 키는 발급 응답·클립보드·다운로드 파일에 들어갑니다. 같은 웹 연결 창에서 복사와 다운로드는 같은 키를 사용합니다.
- 키는 90일 후 만료됩니다. 같은 계정으로 재발급하면 이전 키가 폐기되고 플레이어 기록은 유지됩니다.
- 웹의 연결 해제는 서버의 키를 무효화합니다. 게임의 이 PC 연결 해제는 로컬 저장 키와 대기 중 업로드를 제거합니다. 과거 점수는 유지됩니다. 이미 전송 중인 요청은 완료될 수 있습니다.
- 파일을 분실하면 같은 계정으로 다시 발급하세요. 파일이 유출되면 즉시 연결 해제 또는 재발급하세요.
- 연결 정보는 비밀입니다. 공유·Git 커밋·스크린샷에 포함하지 마세요. 게임은 등록한 키를 Windows DPAPI로 암호화해 저장하고 화면에는 키를 표시하지 않습니다. 다른 Windows 계정으로 옮기면 웹에서 다시 연결하세요. 다운로드한 원본 파일은 여전히 비밀입니다.

## 제출·비교 규칙
차트 SHA-256, 키 모드, 배속, 규칙 버전, 게이지, 랜덤, 변환 알고리즘/프리셋, 정렬된 모드 목록이 같은 기록끼리 비교합니다.
네 가지 지표를 게임이 저장한 값으로 보냅니다.

| 표시 | 전송 필드 | 의미 |
| --- | --- | --- |
| 점수 | `score` | 기존 최종 네이티브 점수(현재 최대 10,000) |
| 상세 스코어 | `detail_score` | 판정별 누적 정수: PG×5 + GR×3 + GD×1 |
| 정확도 | `accuracy` | 기존 판정 종류별 가중 정확도, 0~100% |
| 상세 정확도 | `detailed_accuracy` | 기존 판정 타이밍을 반영한 세부 정확도, 0~100% |

표시 자릿수로 반올림하기 전 값을 전송하므로 미세한 정확도 차이도 웹의 비교에 사용할 수 있습니다. 기존 점수 계산과 로컬 기록 선정은 변경하지 않습니다.

웹의 개인별 최고 기록과 전체 순위는 **점수 → 상세 스코어 → 상세 정확도 → 정확도 → 최대 콤보** 순서로 높은 값을 우선합니다. 앞 항목이 같을 때 다음 항목으로 비교하며 다섯 값이 모두 같으면 공동 순위입니다. 접수 시각과 ID는 완전 동률 기록의 표시 순서만 안정화합니다.

옛 클라이언트가 보낸 상세 스코어·상세 정확도 없는 기록은 웹에서 미기록으로 표시합니다. 임의로 0이나 정확도를 복사해 채우지 않으며 같은 점수에서는 상세 값이 있는 기록을 앞에 둡니다.
중복 리플레이 해시는 같은 플레이어에게 두 번 저장되지 않습니다.
자동 플레이, 연습, 중단, 일시정지, 원미스 실패, 코스, 노트 추가, 커스텀 규칙 기록은 클라이언트에서 제외합니다.

Sites는 게임이 제출한 값의 형식·인증·중복 여부를 검사합니다. C++ 리플레이 재실행 검증은 하지 않습니다.
따라서 'client_submitted' 커뮤니티 기록이며 공식 부정행위 방지/서버 검증 기록으로 취급하면 안 됩니다.
차트 파일·음원·리플레이 파일·로컬 경로·게임 프로필 이름을 전송하지 않습니다.

## 네트워크와 실패
- 게임은 HTTPS *.chatgpt.site의 /api/upload에만 연결합니다. 인증서 검사와 리다이렉트 차단을 유지합니다.
- 사이트가 비공개이면 OpenAI의 방문자 로그인 계층이 게임 요청을 막으므로, 게임 자동 업로드는 사이트 인터넷 공개 후 동작합니다.
- 업로드 전용 작업 스레드가 최대 16개를 처리합니다. 일시적인 연결 오류, HTTP 429/5xx는 최대 3번 시도합니다.
- 업로드 결과는 게임 결과 메시지와 F10 → 웹 리더보드에 표시됩니다. F10의 최근 상태는 현재 게임 실행 동안 유지됩니다. 로컬 결과·리플레이는 보존됩니다.
- 종료 시 미완료 대기열은 취소됩니다. 실패·취소된 기록을 다음 실행에서 자동 재전송하지는 않습니다.
- 연결은 같은 게임 설치의 모든 로컬 프로필에서 공유됩니다. 다른 계정으로 올리려면 F10에서 새 연결 정보를 등록하세요.
- 저장 파일은 config/sites-leaderboard.dpapi이며, 이전 수동 설치의 sites-leaderboard.json도 읽을 수 있습니다. 인게임으로 다시 등록하면 이전 평문 설정은 제거됩니다.
- F10 → 웹 리더보드 탭은 마우스로 선택하거나 Ctrl+Tab으로 계정/웹 화면을 전환할 수 있습니다.

## 코드 위치와 검증
- src/app/MenuAppTail.inl: 플레이 완료 시 enqueue; 리플레이 재생/코스/중단 제외.
- src/app/SitesLeaderboardClient.*: 개인정보 없는 payload, 백그라운드 큐·연결 변경 시 대기열 취소.
- src/app/SitesLeaderboardConnection.*: 입력 검증, DPAPI 저장·원자적 교체·불러오기·해제.
- src/app/MenuAppAccount.cpp와 src/render/MenuWindow_draw_account_body.inl: F10 웹 연결 화면·파일 선택·붙여넣기.
- src/app/RankedRecordsClient.cpp: 전용 HTTPS 업로드; 공식 검증 경로와 별도 endpoint.
- src/app/MenuApp.cpp: 업로드 상태 메시지와 종료 처리.
- tests/unit/test_sites_leaderboard.cpp: URL/키, 제외 조건, 실제 UTC 형식, 경로 비노출.
- tests/smoke/sites_payload_smoke.cpp: 웹과 공유하는 합성 계약 fixture 생성. 게임 설치 폴더에서 --inspect <result.json> <chart-title>로 원본 해시·리플레이·키 로딩을 비밀 출력 없이 진단하고, --retry로 실제 제출합니다. --retry는 사이트에 기록을 쓰므로 실제 사용자 요청 기록에만 사용합니다.

빌드: cmake --build build --config Release --target tenriff bms_parser_tests sites_payload_smoke
검증: ctest --test-dir build -C Release --output-on-failure
이 문서는 1.7.7 클라이언트의 공개 Sites 프로토콜 문서입니다. 서버 소스, DB, 배포 설정, 운영 로그, 계정 연결 파일, 업로드 키는 공개 소스와 패키지에 포함하지 않습니다. 게임/리플레이/페이로드 스키마 버전은 유지하며 상세 값이 없는 옛 웹 기록은 값을 새로 계산한 것처럼 표시하지 않습니다.

## 2026-09-13 업로드 수정
초기 키 상태 동기화가 이미 떼어진 레인에 중복 key-up을 기록해 엄격한 리플레이 검증에 실패하던 오류를 수정했습니다. GameplayEngine::sync_input_state는 실제 상태가 바뀔 때만 기록하며 리플레이 검증 규칙은 유지합니다. tests/unit/test_gameplay_engine.cpp에 초기 10레인 동기화와 반복 상태 회귀 검증이 있습니다.

기록 메뉴의 기존 서버 기록은 원래 TenRiff API 조회입니다. 해당 서버의 시간 초과는 Sites 웹 업로드 상태가 아닙니다. 웹 기록은 F10 → 웹 리더보드에서 사이트를 열어 확인하세요. FAILED도 지원 조건이면 결과 저장 직후 제출되며, 웹에서 새로고침하면 반영됩니다. 몇 시간 단위의 예약 집계는 없습니다.

## 2026-09-15 무입력 종료 수정

마지막 노트 이후 입력하지 않아도 실제 후주 재생과 최소 결과 대기가 끝나면 자동으로 결과·리플레이를 저장하고 업로드 대기열에 넣습니다. 기존에는 시작 시 추정한 음원 길이와 차트 끝 마디까지 기다렸기 때문에 후주가 끝나도 저장이 늦어질 수 있었고, 레인 키로 후주를 건너뛰어야 바로 저장됐습니다. 이제 재생 중인 음원과 예약된 BGM을 기준으로 끝을 판단하며, 실패한 디코드 자산은 대기하지 않습니다. 레인 키를 눌러 후주를 건너뛰는 동작도 계속 사용할 수 있습니다.

테스트는 실제 게임 오디오 콜백에서 마지막 노트만 연주한 뒤 추가 입력 없이 자동 종료, 로컬 파일 저장, 웹 제출 페이로드 생성을 확인합니다. 실제 계정의 웹 등록 여부는 연결 상태와 서버 응답에 따라 달라지며, 이 자동 테스트는 공개 서버에 기록을 올리지 않습니다.
